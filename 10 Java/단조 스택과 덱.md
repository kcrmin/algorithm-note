# 단조 스택과 덱

> **핵심:** 앞으로 정답이 될 수 없는 후보를 제거하고 값의 순서를 유지한다. 각 인덱스는 한 번 들어오고 한 번만 나가므로 전체가 `O(N)`이다.

## 개념

단조 스택은 다음 큰 원소처럼, 새 원소가 이전 원소들의 답을 확정하는 문제에서 사용한다. 단조 덱은 [[슬라이딩 윈도우]]의 최댓값처럼, 뒤에서 더 약한 후보를 지우고 앞에서 범위를 벗어난 후보를 지우는 문제에서 사용한다. 값뿐 아니라 **인덱스**를 저장해야 원소의 위치와 유효 기간을 판단할 수 있다.

## 적용 조건

| 메서드 | 반환값 | 시간 / 공간 |
|---|---|---|
| `nextGreaterIndex(a)` | 각 위치 오른쪽의 첫 엄격히 큰 원소 인덱스, 없으면 `-1` | `O(N)` / `O(N)` |
| `slidingMax(a, k)` | 왼쪽부터 각 길이 `k` 구간의 최댓값 | `O(N)` / 덱 `O(k)`, 결과 `O(N - k + 1)` |

- 다음 큰 원소는 **오른쪽에서 처음 만나는 `>` 값**을 구한다. 같은 값은 답이 아니다.
- 슬라이딩 최댓값은 `1 ≤ k ≤ N`이어야 한다. 빈 배열의 다음 큰 원소 결과는 빈 배열이며, 빈 배열에는 유효한 양수 윈도우가 없다.
- [[스택과 큐]]의 기본 연산에, 후보의 값 순서를 유지하는 제거 조건을 더한 것이다.

## Java 템플릿

```java
import java.util.ArrayDeque;
import java.util.Arrays;
import java.util.Deque;

final class Monotonic {
    static int[] nextGreaterIndex(int[] a) {
        int[] next = new int[a.length];
        Arrays.fill(next, -1);
        Deque<Integer> stack = new ArrayDeque<>();

        for (int i = 0; i < a.length; i++) {
            while (!stack.isEmpty() && a[stack.peek()] < a[i]) {
                next[stack.pop()] = i;
            }
            stack.push(i);
        }
        return next;
    }

    static int[] slidingMax(int[] a, int k) {
        if (k <= 0 || k > a.length) throw new IllegalArgumentException();
        int[] result = new int[a.length - k + 1];
        Deque<Integer> deque = new ArrayDeque<>();

        for (int i = 0; i < a.length; i++) {
            while (!deque.isEmpty() && deque.peekFirst() <= i - k) {
                deque.pollFirst();
            }
            while (!deque.isEmpty() && a[deque.peekLast()] <= a[i]) {
                deque.pollLast();
            }
            deque.addLast(i);
            if (i >= k - 1) result[i - k + 1] = a[deque.peekFirst()];
        }
        return result;
    }
}
```

**관련 개념:** 

| 현재 `i:값` | 제거 후 추가한 스택 | 확정된 답 |
|---|---|---|
| `0:2` | `[0:2]` | 없음 |
| `1:2` | `[0:2, 1:2]` | 같은 값은 제거하지 않음 |
| `2:1` | `[0:2, 1:2, 2:1]` | 없음 |
| `3:3` | `[3:3]` | `next[2] = next[1] = next[0] = 3` |
| `4:2` | `[3:3, 4:2]` | 없음 |

결과는 `[3, 3, 3, -1, -1]`이다. 스택에는 아직 답을 못 찾은 인덱스만 남고, 값은 아래에서 위로 비증가한다. 새 값이 꼭대기보다 크면 그 원소의 답이 확정된다. 더 가까운 큰 값이 앞서 있었다면 그때 이미 빠졌어야 하므로, 지금 찾은 `i`가 **가장 가까운** 큰 원소다. 조건이 `<`이므로 같은 값은 스택에 남아 엄격한 `>` 조건을 지킨다.

**슬라이딩 최댓값:** `a = [4, 2, 3, 1, 0]`, `k = 3`에서 덱은 앞→뒤 순서다.

| `i` | 제거 이유 | 남은 덱 | 완성된 윈도우의 최댓값 |
|---|---|---|---:|
| 0 | 없음 | `[0:4]` | 아직 길이 3 미만 |
| 1 | 없음 | `[0:4, 1:2]` | 아직 길이 3 미만 |
| 2 | 뒤의 `1:2`가 새 값 3 이하 | `[0:4, 2:3]` | 4 |
| 3 | 앞의 인덱스 0이 `i - k = 0` 이하 | `[2:3, 3:1]` | 3 |
| 4 | 없음 | `[2:3, 3:1, 4:0]` | 3 |

- **만료는 인덱스로 판단한다.** 현재 윈도우는 `[i - k + 1, i]`이므로 `index ≤ i - k`인 원소는 범위 밖이다. 덱의 인덱스는 증가하므로 만료된 후보는 항상 앞에 있다.
- **뒤에서 새 값 이하를 지운다.** 더 늦게 들어온 값이 같거나 더 크면, 이전 후보보다 크기가 불리하지 않고 더 늦게 만료된다. 이전 후보가 앞으로 최댓값이 될 상황이 없으므로 제거한다. 같은 값도 지워 최신 인덱스를 남겨도 안전하다.
- **앞이 현재 최댓값이다.** 덱의 값은 앞에서 뒤로 엄격히 감소하고, 모든 인덱스가 현재 윈도우 안에 있다. 첫 완성 시점은 `i = k - 1`, 결과 인덱스는 윈도우 시작점인 `i - k + 1`이다.

두 코드 모두 `while`이 있지만, 인덱스 하나가 제거되면 다시 들어오지 않는다. 전체 추가 횟수와 제거 횟수가 각각 최대 `N`이므로 총 시간은 `O(N)`이다.

## 주의점

- 스택의 `<`를 `<=`로 바꾸면 같은 값도 다음 답으로 확정되어 ‘다음 크거나 같은 원소’가 된다. 중복값 조건을 문제 정의와 맞춰야 한다.
- 덱에서는 같은 값 중 최신 위치만 남겨도 되므로 `<=`를 쓴다. 스택의 엄격한 비교와 목적이 다르다.
- `nextGreaterIndex`는 값이 아니라 인덱스를 반환한다. 값이 필요하면 결과가 `-1`이 아닌 위치에서 `a[next[i]]`로 읽는다.
