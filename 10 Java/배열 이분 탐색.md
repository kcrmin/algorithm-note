# 배열 이분 탐색

> **핵심:** lower bound는 첫 `>= target`, upper bound는 첫 `> target`. 위치가 없으면 배열 길이.

## 개념

정렬된 배열에서 값과 비교 결과가 바뀌는 첫 위치를 찾는다. `[left,right)`는 답이 있을 수 있는 경계 구간이며 right는 검사하지 않는 끝 다음 위치다. 같은 값이 여러 개여도 첫 위치와 끝 다음 위치를 구할 수 있다.

## 적용 조건

배열은 오름차순. 시간 `O(log n)`, 공간 `O(1)`. 빈 배열도 두 경계가 모두 0이다.

## Java 템플릿

```java
class ArrayBounds {
    static int lowerBound(int[] arr, int target) {
        int left = 0, right = arr.length;
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (arr[mid] >= target) right = mid;
            else left = mid + 1;
        }
        return left;
    }
    static int upperBound(int[] arr, int target) {
        int left = 0, right = arr.length;
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (arr[mid] > target) right = mid;
            else left = mid + 1;
        }
        return left;
    }
}
```

> [!info]- 원리와 코드 설명
>
> `[1,3,3,5]`에서 target=3이면 lower=1, upper=3이다. `upper-lower=2`가 등장 횟수다.
>
> lower bound에서 처음 `[0,4)`, mid=2의 값은 3이다. 조건을 만족하지만 앞에 다른 3이 있을 수 있어 right=2로 둔다. 다음 mid=1도 3이라 right=1, 다음 mid=0은 1이라 left=1. 첫 위치 1을 남긴다.
>
> upper bound는 같은 3을 넘어가야 하므로 조건이 `>`다. mid=2의 3은 조건을 만족하지 않아 left=3, mid=3의 5는 만족하므로 right=3. 결과는 3이다.
>
> right를 n으로 둘 수 있는 이유는 mid가 반복 중 항상 n보다 작기 때문이다. 모든 원소가 target보다 작으면 left가 n에 도달해 종료하지만 arr[n]을 읽지 않는다.
>
> ### 주의점
>
> - 반환값이 `arr.length`면 실제 원소가 아니다. 값을 읽기 전에 확인한다.
> - `Arrays.binarySearch`는 중복값의 첫 위치를 보장하지 않는다.
> - last true를 찾는 닫힌 구간 템플릿과 upper bound를 같은 이름으로 부르지 않는다.
