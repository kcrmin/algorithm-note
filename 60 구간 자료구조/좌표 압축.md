# 좌표 압축

> **핵심:** 정렬 → 중복 제거 → 원래 값을 순위 번호로 바꾼다.

## 개념

좌표 압축은 실제 값 대신 정렬된 서로 다른 값의 순위를 사용하는 방법이다. 값의 크기 범위를 작은 인덱스 범위로 바꾸면서 대소 관계와 같은 값 여부를 보존한다.

## 적용 조건

값은 크고 듬성듬성하지만 상대적인 대소 관계만 필요할 때 쓴다. `[-100, 10억]`을 그대로 배열 인덱스로 쓰기 어렵다면 순위 `0,1`로 바꾼다. 정렬 시간 `O(n log n)`, 추가 공간 `O(n)`.

## Java 템플릿

```java
import java.util.*;

class CompressionTemplate {
    static int[] compress(int[] arr) {
        int[] sorted = arr.clone();
        Arrays.sort(sorted);
        Map<Integer, Integer> rank = new HashMap<>();
        for (int value : sorted) {
            if (!rank.containsKey(value)) rank.put(value, rank.size());
        }
        int[] compressed = new int[arr.length];
        for (int i = 0; i < arr.length; i++) {
            compressed[i] = rank.get(arr[i]);
        }
        return compressed;
    }
}
```

> [!info]- 원리와 코드 설명
>
> `[100,-5,100,20]`을 정렬하면 `[-5,20,100,100]`이다. 처음 본 순서대로 `-5→0`, `20→1`, `100→2`를 부여한다. 원래 배열을 다시 읽으면 `[2,0,2,1]`이 된다. 같은 값은 같은 번호를 가져야 해서 중복이면 새 번호를 만들지 않는다.
>
> Map은 조회 도구다. **정렬한 배열을 순회하기 때문에** 번호가 대소 순서를 유지한다. HashMap 자체의 순회 순서를 믿고 번호를 부여하면 안 된다.
>
> ### 주의점
>
> - 실제 거리는 보존하지 않는다. `20-(-5)=25`지만 압축 후 차이는 1이다.
> - 원본은 clone으로 보존한다. 최종 결과는 원래 인덱스 순서여야 한다.
> - 단순 빈도 집계만 필요하다면 압축 없이 HashMap으로 끝낼 수 있다.
