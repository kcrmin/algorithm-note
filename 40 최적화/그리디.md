# 그리디

그리디는 지금 선택을 확정해도 전체 최적해를 잃지 않는 기준으로 고르는 방법이다.

> **기억:** 기준으로 정렬 → 고를 수 있으면 선택 → 선택 기준 상태 갱신.

**전제:** 회의 [시작,끝), 시작<끝. 겹치지 않게 최대 개수 선택. O(n log n).

## 템플릿

```java
Arrays.sort(meetings, Comparator.comparingInt(a -> a[1]));
int end = Integer.MIN_VALUE;
int answer = 0;
for (int[] meeting : meetings) {
    if (meeting[0] < end) continue;
    answer++;
    end = meeting[1];
}
```

## 왜 이렇게 쓰나

- 빨리 끝나는 회의가 다음 회의를 놓을 공간을 가장 많이 남긴다.
- 최적해의 첫 회의를 더 빨리 끝나는 회의로 바꿔도 뒤 회의들을 방해하지 않는다. 그래서 이 선택을 확정할 수 있다.
- `[시작,끝)`이라 이전 끝과 다음 시작이 같으면 이어 붙일 수 있다.

`[1,4], [2,3], [3,5]` → 끝 순서로 `[2,3]` 선택 → `[1,4]` 제외 → `[3,5]` 선택, 2개. 이 정당화는 회의 선택의 것이며 다른 문제의 그리디 기준은 별도로 성립해야 한다.

> [!info]- 더 자세한 설명
>
> 회의가 `(1,4), (2,3), (3,5), (4,6), (5,7)`이면 끝나는 시간 순서는 다음과 같다.
>
> | 현재 회의 | 직전 `lastEnd` | 판단 | 선택 수 |
> |---|---:|---|---:|
> | `(2,3)` | 가장 작은 값 | 선택, `lastEnd=3` | 1 |
> | `(1,4)` | 3 | 시작 1이 3보다 작아서 제외 | 1 |
> | `(3,5)` | 3 | 시작=직전 끝, 선택 | 2 |
> | `(4,6)` | 5 | 겹치므로 제외 | 2 |
> | `(5,7)` | 5 | 선택 | 3 |
>
> **왜 가장 먼저 끝나는 회의를 골라도 되는가?** 어떤 최적해의 첫 회의가 4에 끝나고, 우리가 고른 회의가 3에 끝난다고 하자. 첫 회의를 우리 회의로 바꿔도 다음 회의들이 시작할 공간은 줄어들지 않는다. 개수도 그대로다. 남은 회의에 같은 이유를 반복할 수 있다.
>
> 반대로 가장 먼저 시작하는 회의를 고르면 `(1,10)` 하나를 고르고 `(2,3), (3,4), (4,5)` 세 개를 놓칠 수 있다. “그럴듯한 정렬 기준”만으로는 부족하다.
>
> **동전에도 무조건 적용하면 안 된다.** 동전 `1, 3, 4`로 금액 6을 만들 때 큰 동전부터 고르면 `4+1+1`로 3개다. 최적은 `3+3`으로 2개다. 선택을 확정할 근거가 없으면 [[DP]]나 [[완전탐색과 시뮬레이션]]을 검토한다.
>
> ### 주의점
>
> - 입력의 두 값이 시작/끝 중 무엇인지 먼저 확인한다. 위 코드는 `[0]=시작`, `[1]=끝`이다.
> - 양끝을 모두 포함하는 구간이고 경계 접촉도 겹침으로 친다면 조건이 달라진다. 문제의 “겹친다” 정의를 읽는다.
> - `count++`와 `lastEnd=end`는 **선택했을 때만** 실행한다.
> - 정렬 비교는 `a[1] - b[1]` 대신 `comparingInt`를 써서 뺄셈 오버플로를 피한다.
> - 이 코드는 입력의 바깥 배열만 복사한다. 회의 내부 값은 바꾸지 않고 순서만 정렬한다.
> - 최소 비용·최대 보상 등으로 목표가 바뀌면 같은 템플릿을 그대로 붙이지 않는다.
>

> [!example]- 준비 코드 · 전체 구현
>
> 필요한 import와 초기화까지 포함한 전체 코드다. 각 코드 블록은 별도 예시다.
>
> ```java
> import java.util.*;
>
> class GreedyTemplate {
>     static int maxMeetings(int[][] meetings) {
>         int[][] sorted = meetings.clone();
>         Arrays.sort(sorted,
>                 Comparator.comparingInt(meeting -> meeting[1]));
>
>         long lastEnd = Long.MIN_VALUE;
>         int count = 0;
>
>         for (int[] meeting : sorted) {
>             int start = meeting[0];
>             int end = meeting[1];
>
>             if (start < lastEnd) continue;
>             count++;
>             lastEnd = end;
>         }
>         return count;
>     }
> }
> ```
