# 힙

> **암기 한 줄:** 반복해서 가장 작은 값 하나를 꺼내면 `PriorityQueue`, 가장 큰 값이면 비교 순서를 뒤집는다.

## 언제 쓰나

- 후보의 삽입과 현재 최솟값/최댓값 조회가 섞여 있을 때 쓴다.
- 한 번 정렬해서 순서대로 읽기만 하면 [[정렬]]이 더 단순하다.
- `offer`는 삽입, `peek`는 맨 앞 확인, `poll`은 맨 앞 제거와 반환이다.
- `offer/poll`은 `O(log N)`, `peek`는 `O(1)`, 원소 저장 공간은 `O(N)`.
- 아래 문제는 **모든 값이 0 이상**이고, 작은 두 값을 `작은 값 + 2 × 다음 값`으로 합친다.
- 계산 중 값이 `long` 범위 안에 들어온다고 가정한다.

## 외울 템플릿

현재 최솟값이 목표보다 작으면 작은 두 개를 꺼내 합친다. 두 개가 없으면 실패다.

```java
import java.util.*;

class HeapTemplate {
    static int mixUntilAtLeast(long[] values, long target) {
        PriorityQueue<Long> pq = new PriorityQueue<>();
        for (long value : values) pq.offer(value);

        int count = 0;
        while (!pq.isEmpty() && pq.peek() < target) {
            if (pq.size() < 2) return -1;

            long first = pq.poll();
            long second = pq.poll();
            pq.offer(first + 2L * second);
            count++;
        }
        return pq.isEmpty() ? -1 : count;
    }
}
```

이 문제의 전체 시간은 삽입과 합치기를 합해 `O(N log N)`, 공간은 `O(N)`이다. 빈 입력은 조건을 만족할 원소가 없으므로 이 메서드에서 `-1`로 정했다.

## 왜 이렇게 쓰나

값 `1, 2, 3, 9`, 목표 7을 추적한다. 아래 표는 이해를 위해 원소를 정렬해 적었다.

| 회차 | 꺼낸 값 | 새 값 | 남은 값 | 최솟값 |
|---|---|---:|---|---:|
| 시작 | — | — | `1,2,3,9` | 1 |
| 1 | 1, 2 | `1+2×2=5` | `3,5,9` | 3 |
| 2 | 3, 5 | `3+2×5=13` | `9,13` | 9 |

최솟값이 7 이상이면 나머지도 7 이상이므로 끝난다. 답은 2다. `1` 하나만 있는데 목표가 7이면 합칠 상대가 없어 `-1`이다.

힙은 **현재 맨 앞만 보장**한다. `for-each`나 `pq.toString()`은 정렬된 순서를 보장하지 않는다. 순서대로 처리하려면 `poll()`을 반복한다.

## 바꿀 부분과 실수

최댓값이 필요하면 위 코드의 큐 선언을 다음 선언으로 교체한다. 이는 정렬 기준을 바꾸는 문법이며, 위 합치기 문제에서는 최소 힙을 유지해야 한다.

| 목적 | 선언 |
|---|---|
| 최소 힙 | `PriorityQueue<Long> pq = new PriorityQueue<>();` |
| 최대 힙 | `PriorityQueue<Long> pq = new PriorityQueue<>(Comparator.reverseOrder());` |
| `[번호, 비용]` 중 비용 최소 | `PriorityQueue<long[]> pq = new PriorityQueue<>(Comparator.comparingLong(a -> a[1]));` |

- 객체·배열을 넣을 때는 어떤 필드를 비교할지 정한다. 비용이 같을 때 번호도 비교해야 한다면 `thenComparingLong(a -> a[0])`을 붙인다.
- 비교자에서 `(int)(a[1]-b[1])`처럼 빼지 않는다. 차이가 자료형 범위를 넘거나 강제 변환으로 잘릴 수 있다.
- 빈 큐의 `peek/poll`은 `null`이다. `long x = pq.poll()`처럼 언박싱하면 예외가 나므로 먼저 크기를 확인한다.
- 큐에 넣은 객체의 우선순위 필드를 직접 바꿔도 힙은 자동 재정렬되지 않는다.
- 임의 원소의 갱신·삭제가 많은 문제는 기본 템플릿과 구분한다. 필요할 때 [[고급 주제 안내]]의 lazy deletion을 확인한다.
- 버전을 쓴다면 **현재 버전을 한 번 올리고 그 값을 새 원소에 그대로 저장**한다. 저장하면서 다시 `version[id]++`하면 새 원소가 즉시 오래된 버전이 되는 실수를 만든다.
- 작은 두 값을 고른다는 규칙은 이 문제의 조건이다. 모든 최적화 문제를 힙으로 해결할 수 있다는 뜻은 아니다.
