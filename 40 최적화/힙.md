# 힙

> **핵심:** 루트에는 최우선 원소. 삽입·제거는 O(log n), 맨 앞 확인은 O(1).

## 개념

힙은 완전이진트리 모양을 유지하면서 부모와 자식 사이의 우선순위를 지키는 자료구조다. 최소 힙에서는 부모가 자식보다 작거나 같아서 루트에 최솟값이 있지만, 전체 원소가 정렬된 것은 아니다.

우선순위 큐는 우선순위가 높은 원소부터 꺼내는 자료형이고, Java의 `PriorityQueue`는 힙으로 구현한다. 들어온 시간순으로 꺼내는 일반 큐와 처리 기준이 다르다.

## 적용 조건

삽입과 현재 최솟값/최댓값 추출이 섞일 때 사용한다. `offer/poll` O(log n), `peek` O(1), 저장 공간 O(n). 한 번 정렬해 순서대로 읽는 경우는 정렬로 충분하다.

## Java 템플릿

다음 메서드는 값 n개를 넣고 작은 값 k개를 순서대로 꺼내는 예시다. 전제는 `0 <= k <= values.length`.

```java
import java.util.*;

class HeapTemplate {
    static int[] smallestK(int[] values, int k) {
        PriorityQueue<Integer> pq = new PriorityQueue<>();
        for (int value : values) pq.offer(value);
        int[] result = new int[k];
        for (int i = 0; i < k; i++) {
            result[i] = pq.poll();
        }
        return result;
    }
}
```

| 목적 | 선언 |
|---|---|
| 최소 힙 | `PriorityQueue<Integer> pq = new PriorityQueue<>();` |
| 최대 힙 | `PriorityQueue<Integer> pq = new PriorityQueue<>(Comparator.reverseOrder());` |
| `[번호, 비용]`의 비용 최소 | `PriorityQueue<long[]> pq = new PriorityQueue<>(Comparator.comparingLong(a -> a[1]));` |

`offer(value)`는 삽입, `peek()`는 맨 앞 확인, `poll()`은 맨 앞 제거와 반환이다. 처리 중 새 후보가 생기면 같은 큐에 다시 offer할 수 있다.

> [!info]- 원리와 코드 설명
>
> 2를 넣은 뒤 5, 3을 넣으면 루트는 2다. poll로 2를 꺼내면 마지막 원소로 빈자리를 채우고, 부모·자식 순서를 복구해 루트가 3이 된다. 그 상태에서 1을 offer하면 부모보다 작은 동안 위로 올라가 루트가 1이 된다. 다음 poll은 1이다.
>
> 완전이진트리의 높이가 O(log n)이므로 새 값이 위로 올라가거나 제거 후 아래로 내려가는 단계도 O(log n)이다. 루트는 곧바로 읽을 수 있어 peek는 O(1)이다.
>
> `[2,5,3]`을 담았다고 내부 저장 순서가 `[2,3,5]`라는 뜻은 아니다. **모든 부모가 자식보다 작다**는 관계만 보장한다. for-each나 toString으로 읽으면 정렬된 순서가 보장되지 않고, poll을 반복해야 순서가 나온다.
>
> ### 주의점
>
> - 빈 큐의 peek/poll은 null이다. 바로 int로 받으면 언박싱 오류가 나므로 먼저 isEmpty나 size를 확인한다.
> - 비교 함수는 Integer.compare/Long.compare를 사용한다. 두 값을 빼면 오버플로우로 순서가 뒤집힐 수 있다.
> - 들어간 객체의 비교 필드를 나중에 바꿔도 힙은 자동 재정렬되지 않는다.
> - 특정 원소를 찾아 remove하는 것은 O(n)이다. 빈번한 갱신·삭제는 버전 기반 지연 삭제를 사용할 수 있다.
> - 위 예시의 시간은 O(n log n + k log n)이다. k개만 유지하는 별도 top-k 방식과는 저장 대상이 다르다.
