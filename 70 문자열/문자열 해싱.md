# 문자열 해싱

> **핵심:** `prefix[r] - prefix[l] × power[r - l]`로 앞부분의 기여를 제거한다. 같은 길이의 해시가 다르면 문자열도 다르지만, 해시가 같다고 문자열까지 같다는 보장은 없다.

## 개념

문자열 해싱은 문자를 정수로 바꾸고 다항식처럼 누적해 부분 문자열을 짧은 정수로 요약한다. 접두사 해시와 거듭제곱을 미리 계산하면 임의의 구간 해시를 `O(1)`에 얻어 반복 비교의 빠른 필터로 사용할 수 있다. 모듈러 연산으로 서로 다른 문자열이 같은 값이 되는 충돌이 있으므로 정확한 동등성 판정에는 실제 문자 비교가 필요하다.

## 적용 조건

- 고정된 문자열에서 여러 부분 문자열을 비교할 때 사용한다. 문자가 수정되면 접두사 배열을 다시 만들어야 한다.
- 길이 `N`의 문자열 전처리는 시간·공간 `O(N)`, `[left, right)` 해시 질의는 `O(1)`이다.
- 아래 `sameSubstring`은 해시가 같을 때 `regionMatches`로 검증하므로 **정확한 비교**다. 길이 `L`인 구간의 비교는 최악 `O(L)`이며, 해시 충돌 또는 실제 일치가 많으면 전체 비교 시간도 커진다.
- 두 해시를 사용해도 충돌 가능성이 사라지지는 않는다. 확정적인 패턴 검색에는 [[KMP]]를 사용할 수 있다.

## Java 템플릿

```java
import java.util.Objects;

public final class StringHash {
    private static final long MOD = 1_000_000_007L;
    private static final long BASE = 911_382_323L;

    private final String text;
    private final long[] prefix;
    private final long[] power;

    public StringHash(String text) {
        this.text = Objects.requireNonNull(text, "text");
        int n = text.length();
        prefix = new long[n + 1];
        power = new long[n + 1];
        power[0] = 1;

        for (int i = 0; i < n; i++) {
            long value = text.charAt(i) + 1L;
            prefix[i + 1] = (prefix[i] * BASE + value) % MOD;
            power[i + 1] = power[i] * BASE % MOD;
        }
    }

    // 0-based 반열린 구간 [left, right).
    public long hash(int left, int right) {
        checkRange(left, right);
        long removed = prefix[left] * power[right - left] % MOD;
        return (prefix[right] - removed + MOD) % MOD;
    }

    // 해시는 필터로 쓰고, 최종 결과는 실제 문자 비교로 확정한다.
    public boolean sameSubstring(int left, int right,
                                 StringHash other,
                                 int otherLeft, int otherRight) {
        Objects.requireNonNull(other, "other");
        checkRange(left, right);
        other.checkRange(otherLeft, otherRight);
        int length = right - left;
        if (length != otherRight - otherLeft) {
            return false;
        }
        if (hash(left, right) != other.hash(otherLeft, otherRight)) {
            return false;
        }
        return text.regionMatches(left, other.text, otherLeft, length);
    }

    private void checkRange(int left, int right) {
        if (left < 0 || left > right || right > text.length()) {
            throw new IndexOutOfBoundsException("invalid substring range");
        }
    }
}
```

> [!info]- 원리와 코드 설명
>
> 문자값을 `v`, 밑을 `B`라고 하면 `prefix[i + 1] = prefix[i] × B + v(text[i])`다. 예를 들어 `abc`의 해시는 `aB² + bB + c`가 된다. 이때 `prefix[l]`을 구간 길이만큼 곱하면 `prefix[r]`에서 제거할 앞부분의 자릿수가 맞춰진다. 모든 계산은 `MOD`로 나눈 나머지를 사용한다.
>
> 원리를 보기 위한 **작은 예시 상수**를 `a = 1`, `b = 2`, `c = 3`, `B = 10`, `MOD = 101`로 두자. 실제 템플릿의 상수와 문자 매핑은 위 코드 그대로 사용한다. `text = abc`의 접두사 해시는 다음과 같다.
>
> | 접두사 길이 `i` | 0 | 1 | 2 | 3 |
> |---|---|---|---|---|
> | 접두사 | 빈 문자열 | a | ab | abc |
> | `prefix[i]` | 0 | 1 | 12 | `123 % 101 = 22` |
>
> 부분 문자열 `bc`인 `[1, 3)`을 추출하려면 길이 2만큼의 자릿수를 맞춰 앞의 `a`를 뺀다.
>
> 1. 나머지를 취하기 전 식은 `123 - 1 × 100 = 23`이다. 남은 23은 `b × 10 + c`다.
> 2. 저장된 나머지로 계산하면 `prefix[3] - prefix[1] × power[2] = 22 - 100 = -78`이다.
> 3. `(22 - 100 + 101) % 101 = 23`으로 정규화하면 같은 결과를 얻는다.
>
> 같은 내용의 구간은 시작 위치가 달라도 앞부분을 제거한 뒤 같은 다항식이 남는다. 해시가 같아도 충돌일 수 있으므로 `sameSubstring`은 마지막에 두 구간의 실제 문자를 비교한다.
>
> `prefix[right] - removed`는 음수일 수 있다. 두 항이 모두 `[0, MOD)`에 있으므로 `MOD`를 한 번 더하고 `% MOD`를 하면 `[0, MOD)`로 정규화된다. 구간 길이만큼의 거듭제곱을 곱해 빼므로 구간의 시작 위치가 달라도 같은 문자열은 같은 해시를 갖는다.
>
> ### 주의점
>
> - 비교 전에 길이도 확인한다. 해시값 하나는 문자열 길이를 보존하지 않는다.
> - 곱셈 피연산자가 `long`이어야 한다. 위 상수에서는 모든 나머지가 `MOD` 미만이어서 가장 큰 곱도 약 `10^18` 미만이고 `long` 범위에 들어간다. 상수를 바꾸면 이 상한을 다시 확인한다.
> - 빈 구간 `[i, i)`의 해시는 0이다. 문자와 위치는 Java의 UTF-16 코드 단위를 기준으로 한다.
> - `% MOD`는 충돌을 만드는 연산이다. 해시만 비교하는 코드의 시간과 정확한 문자 비교까지 하는 코드의 시간을 구분한다.
