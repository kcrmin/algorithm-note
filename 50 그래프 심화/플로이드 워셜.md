# 플로이드 워셜

> **핵심:** 경유점 k를 맨 바깥에 두고, `i→k→j`가 더 짧으면 `i→j`를 바꾼다.

## 개념

플로이드–워셜은 거쳐 갈 수 있는 중간 정점을 하나씩 늘려 모든 정점 쌍의 최단거리를 구하는 DP다. k를 중간 지점으로 허용할 때 i→j와 i→k→j 중 더 짧은 값을 남긴다.

## 적용 조건

- 정점 수가 작고 **모든 정점 쌍**의 최단거리가 필요할 때 쓴다.
- 시간 `O(V³)`, 공간 `O(V²)`이므로 정점 수부터 확인한다. 정점 500개면 3중 반복은 약 1억 2,500만 회다.
- 아래 코드는 유향 그래프, 정점 `0 ~ n-1`, `edges[i]={출발, 도착, 비용}`이다.
- 음수 간선은 가능하지만 **음수 사이클이 없는 입력**을 가정한다. 사이클을 돌수록 비용이 줄어들면 최단거리를 정할 수 없다.
- 도달 불가능은 `INF`로 남긴다. 입력과 모든 유한 최단거리의 절댓값이 `INF`보다 작다고 가정한다.

## Java 템플릿

```java
import java.util.*;

class FloydTemplate {
    static final long INF = Long.MAX_VALUE / 4;

    static long[][] allPairs(int n, int[][] edges) {
        long[][] dist = new long[n][n];
        for (int i = 0; i < n; i++) {
            Arrays.fill(dist[i], INF);
            dist[i][i] = 0;
        }

        for (int[] edge : edges) {
            int from = edge[0];
            int to = edge[1];
            dist[from][to] = Math.min(dist[from][to], edge[2]);
        }

        for (int k = 0; k < n; k++) {
            for (int i = 0; i < n; i++) {
                if (dist[i][k] == INF) continue;

                for (int j = 0; j < n; j++) {
                    if (dist[k][j] == INF) continue;

                    long through = dist[i][k] + dist[k][j];
                    if (through < dist[i][j]) {
                        dist[i][j] = through;
                    }
                }
            }
        }
        return dist;
    }
}
```

> [!info]- 원리와 코드 설명
>
> 간선 `0→1:3`, `1→2:4`, `0→2:10`이 있다고 하자. 초기 거리는 다음과 같다. `∞`는 `INF`다.
>
> | 출발\도착 | 0 | 1 | 2 |
> |---|---:|---:|---:|
> | 0 | 0 | 3 | 10 |
> | 1 | ∞ | 0 | 4 |
> | 2 | ∞ | ∞ | 0 |
>
> 경유점 `k=1`을 허용하면 `dist[0][1]+dist[1][2]=3+4=7`이다. 기존 `dist[0][2]=10`보다 짧으므로 7로 바꾼다. 직접 간선이 없어도 두 구간이 모두 있으면 경로가 생긴다.
>
> **왜 k가 맨 바깥인가?** k회차가 끝난 뒤의 표는 “중간 정점으로 0부터 k까지 써도 되는 최단거리”를 뜻한다. 경유점을 하나씩 늘려야 이전에 계산한 두 부분 경로를 합쳐도 상태의 의미가 유지된다. 단순히 세 정점을 모두 반복한다는 이유로 순서를 바꾸면 한 번의 반복으로 답이 보장되지 않는다.
>
> **왜 대각선은 0인가?** 아무 간선도 지나지 않고 자기 자리에 있는 비용이 0이기 때문이다.
>
> **왜 같은 출발·도착 간선은 min으로 넣는가?** `0→1:3` 다음에 `0→1:8`이 입력되어도 직접 가는 최소 비용은 여전히 3이다. 뒤의 입력으로 덮어쓰면 안 된다.
>
> **왜 INF를 더하지 않는가?** `i→k`가 없는데 `k→j`의 음수 비용을 더하면 `INF-5`처럼 가짜 유한 경로가 생길 수 있다. 두 구간이 모두 유한할 때만 합친다. `INF`에 여유를 둬 두 유한 값의 덧셈 오버플로도 피한다.
>
> ### 주의점
>
> - 무향 그래프면 입력 처리에서 반대 방향 거리도 같은 방식으로 `min` 갱신한다.
> - 반환 뒤 `dist[a][b] == INF`이면 a에서 b로 갈 수 없다. 문제에서 원하는 출력값은 그때 바꾼다.
> - 모든 쌍의 거리를 합산한다면 도달 불가능한 `INF`를 그대로 더하지 않는다.
> - `dist[i][k]`와 `dist[k][j]`의 i/k/j를 바꾸지 않는다. 출발→경유→도착 순서다.
> - 음수 간선이 있는 경우 `INF` 검사 두 줄을 생략하면 특히 틀리기 쉽다.
> - 정점이 많고 시작점 하나의 거리만 필요하면 [[다익스트라]]를 먼저 검토한다. 그 경우 간선은 음수가 없어야 한다.
> - 대각선 음수 여부로 음수 사이클을 판별할 수 있지만, 이 노트의 템플릿은 음수 사이클이 없다는 조건에서 거리만 계산한다.
