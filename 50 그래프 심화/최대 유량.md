# 최대 유량

> 잔여 용량이 양수인 간선만 쓰고, 유량을 보낸 만큼 정방향 용량을 줄이며 역방향 용량을 늘린다.

## 개념

최대 유량은 각 간선의 용량과 중간 정점의 유량 보존을 지키면서 source에서 sink로 보낼 수 있는 총량의 최댓값이다. Dinic은 아직 보낼 수 있는 양과 기존 흐름을 취소할 수 있는 양을 잔여 그래프로 나타내고, BFS로 정한 층을 따라 유량을 보내 이 값을 구한다.

## 적용 조건

- 정점은 `0 ~ n-1`, source와 sink는 서로 다른 유효한 정점이다. `addEdge(from,to,capacity)`는 유향 간선을 추가하며 용량은 음수가 아닌 long 정수다.
- 평행 간선, 실제 반대 방향 간선, 자기 루프를 허용한다. 입력 간선 하나마다 용량 0인 역간선을 **별도로** 만든다.
- 일반 그래프에서 Dinic의 시간복잡도는 `O(V²E)`, 공간은 `O(V+E)`다. E는 입력 간선 수이며 잔여 그래프에는 간선이 2E개 저장된다.
- DFS는 층이 1씩 증가하는 경로만 따라가므로 재귀 깊이는 최악 `O(V)`다. 매우 긴 경로에서는 Java 호출 스택 한계를 고려해야 한다.
- 반환할 최대 유량은 `Long.MAX_VALUE` 이하여야 한다. 개별 용량이 long이라는 사실만으로 총 유량도 long 범위라는 보장은 없다. 범위를 넘는 합산은 `Math.addExact`가 예외로 검출한다.
- `maxFlow`는 내부 잔여 그래프를 변경하며, **이번 호출에서 추가로 보낸 유량**을 반환한다. 같은 source/sink로 바로 다시 호출하면 0이다.
- 최대 유량 계산이 끝난 뒤 `sourceSideOfMinCut(source)`는 최소 컷에서 source 쪽 정점 집합을 반환한다. 계산 전에는 단순한 잔여 그래프 도달 집합이다.

## Java 템플릿

```java
import java.util.*;

class Dinic {
    static class Edge {
        final int to;
        final int reverseIndex;
        long remaining;

        Edge(int to, int reverseIndex, long remaining) {
            this.to = to;
            this.reverseIndex = reverseIndex;
            this.remaining = remaining;
        }
    }

    final List<List<Edge>> graph;
    final int[] level;
    final int[] nextEdge;

    Dinic(int n) {
        graph = new ArrayList<>();
        for (int vertex = 0; vertex < n; vertex++) graph.add(new ArrayList<>());
        level = new int[n];
        nextEdge = new int[n];
    }

    void addEdge(int from, int to, long capacity) {
        if (capacity < 0) throw new IllegalArgumentException("negative capacity");
        int forwardIndex = graph.get(from).size();
        int reverseIndex = graph.get(to).size() + (from == to ? 1 : 0);
        Edge forward = new Edge(to, reverseIndex, capacity);
        Edge reverse = new Edge(from, forwardIndex, 0);
        graph.get(from).add(forward);
        graph.get(to).add(reverse);
    }

    // 잔여 그래프를 갱신하고, 이번 호출에서 추가로 보낸 유량을 반환한다.
    long maxFlow(int source, int sink) {
        if (source == sink) throw new IllegalArgumentException("source equals sink");
        long total = 0;
        while (buildLevels(source, sink)) {
            Arrays.fill(nextEdge, 0);
            while (true) {
                long sent = send(source, sink, Long.MAX_VALUE);
                if (sent == 0) break;
                total = Math.addExact(total, sent);
            }
        }
        return total;
    }

    private boolean buildLevels(int source, int sink) {
        Arrays.fill(level, -1);
        Queue<Integer> queue = new ArrayDeque<>();
        level[source] = 0;
        queue.offer(source);
        while (!queue.isEmpty()) {
            int current = queue.poll();
            for (Edge edge : graph.get(current)) {
                if (edge.remaining <= 0 || level[edge.to] != -1) continue;
                level[edge.to] = level[current] + 1;
                queue.offer(edge.to);
            }
        }
        return level[sink] != -1;
    }

    private long send(int current, int sink, long limit) {
        if (current == sink) return limit;
        List<Edge> edges = graph.get(current);
        for (; nextEdge[current] < edges.size(); nextEdge[current]++) {
            Edge edge = edges.get(nextEdge[current]);
            if (edge.remaining <= 0 || level[edge.to] != level[current] + 1) continue;
            long sent = send(edge.to, sink, Math.min(limit, edge.remaining));
            if (sent == 0) continue;
            edge.remaining -= sent;
            graph.get(edge.to).get(edge.reverseIndex).remaining += sent;
            return sent;
        }
        return 0;
    }

    // maxFlow 종료 후 source와 같은 쪽에 속하는 최소 컷 정점들.
    boolean[] sourceSideOfMinCut(int source) {
        boolean[] reachable = new boolean[graph.size()];
        Queue<Integer> queue = new ArrayDeque<>();
        reachable[source] = true;
        queue.offer(source);
        while (!queue.isEmpty()) {
            int current = queue.poll();
            for (Edge edge : graph.get(current)) {
                if (edge.remaining <= 0 || reachable[edge.to]) continue;
                reachable[edge.to] = true;
                queue.offer(edge.to);
            }
        }
        return reachable;
    }
}
```

> [!info]- 원리와 코드 설명
>
> ### 1. 역간선은 이전 결정을 취소할 수 있는 권리다
>
> 용량이 5인 `u→v`에 2를 보내면 정방향 잔여 용량은 `5-2 = 3`, 역방향 잔여 용량은 `0+2 = 2`가 된다.
>
> ```text
> 보내기 전: u ──5──▶ v     v ──0──▶ u
> 2 보낸 뒤: u ──3──▶ v     v ──2──▶ u
> ```
>
> 나중에 `v→u` 잔여 간선으로 1을 보내는 것은 새로운 물량을 만드는 일이 아니라 기존 `u→v` 흐름 중 1을 취소하는 것이다. 더 좋은 배치를 발견했을 때 이미 보낸 유량을 다른 경로로 돌릴 수 있어야 최대값을 얻는다.
>
> 한 입력 간선의 정방향·역방향 잔여 용량 합은 항상 원래 용량이다. 각각 0 이상이고 합이 원래 long 용량 이내이므로 쌍 내부의 역간선 용량 증가도 long 범위를 넘지 않는다. 전체 유량의 합은 별도로 범위를 확인해야 한다.
>
> ### 2. BFS의 층은 지금 가장 짧은 잔여 경로만 남긴다
>
> source=0, sink=3이고 다음 용량을 갖는 네트워크다.
>
> | 간선 | 용량 |
> |---|---:|
> | 0→1 | 3 |
> | 0→2 | 2 |
> | 1→2 | 1 |
> | 1→3 | 2 |
> | 2→3 | 3 |
>
> 첫 BFS는 `level = [0,1,1,2]`를 만든다. DFS는 `level[next] == level[current]+1`인 간선만 사용한다.
>
> - `0→1→3`으로 `min(3,2)=2`를 보낸다.
> - `0→2→3`으로 `min(2,3)=2`를 보낸다.
> - `1→2`는 양 끝의 층이 모두 1이라 이번 단계에서는 사용하지 않는다.
>
> 현재 총 유량은 4다. 이 층 구조에서는 더 보낼 경로가 없어져 **차단 유량(blocking flow)** 상태가 된다. 이는 전체 최대 유량에 도달했다는 뜻이 아니라 현재 층의 모든 source→sink 경로가 막혔다는 뜻이다.
>
> ### 3. 층을 다시 만들면 남은 우회 경로가 드러난다
>
> 첫 단계 이후 양수인 순방향 잔여 경로에는 다음이 남는다.
>
> ```text
> 0 ──1──▶ 1 ──1──▶ 2 ──1──▶ 3
> ```
>
> 두 번째 BFS의 층은 `[0,1,2,3]`이다. 이제 `1→2`도 다음 층으로 가는 간선이므로 사용할 수 있다. 이 경로로 1을 더 보내면 총 유량은 `4+1=5`다.
>
> 다음 BFS에서 source 0은 더 이상 sink 3에 도달하지 못하므로 종료한다. 코드의 바깥 while은 층을 다시 만드는 과정, 안쪽 while은 현재 층에서 더 보낼 수 없을 때까지 유량을 보내는 과정이다.
>
> ### 4. `nextEdge`는 실패한 간선을 같은 단계에서 다시 보지 않게 한다
>
> `nextEdge[v]`는 정점 v에서 다음으로 검사할 인접 간선 번호다. 용량이 없거나, 다음 층으로 이어지지 않거나, 그 뒤로 sink까지 갈 수 없는 간선은 이번 BFS 단계에서 다시 검사할 필요가 없다.
>
> 유량을 성공적으로 보낸 경우에는 현재 간선 번호를 유지한다. 예를 들어 용량 5인 간선에 2만 보냈으면 남은 3을 같은 간선으로 더 보낼 수 있기 때문이다. 해당 간선으로 더 보낼 수 없을 때에만 for문의 증가식이 다음 간선으로 이동시킨다.
>
> BFS를 다시 수행하면 사용할 수 있는 층과 경로가 달라지므로 `nextEdge`도 모두 0으로 초기화한다. 한 단계에서의 포인터를 다음 단계에 그대로 쓰면 새 경로를 건너뛸 수 있다.
>
> ### 5. 역간선은 정점 번호가 아니라 정확한 위치로 연결한다
>
> `reverseIndex`는 반대쪽 정점의 인접 목록에서 **이 간선과 짝인 역간선의 인덱스**다. 실제 입력에 `u→v`와 `v→u`가 모두 있어도 두 입력 간선은 각자의 잔여 역간선을 따로 가진다. 반대 방향의 실제 입력 간선을 취소용 역간선으로 대신 쓰면 서로 다른 용량이 섞인다.
>
> 자기 루프 `u→u`는 정방향과 역방향이 같은 목록에 들어간다. 추가 전 크기가 2이면 정방향은 인덱스 2, 역방향은 인덱스 3이다. 따라서 정방향의 역간선 인덱스에 1을 더한다. 역방향은 정방향이 있던 인덱스 2를 가리킨다.
>
> 자기 루프는 층이 증가하지 않으므로 실제 유량 경로에는 사용되지 않지만, 자료구조의 짝 관계는 정확하게 유지된다.
>
> ### 6. 최소 컷은 최대 유량의 상한과 일치한다
>
> 최대 유량 계산 후 잔여 그래프에서 source로부터 도달 가능한 정점을 S라고 하자. sink는 S에 없고, S에서 바깥으로 나가는 잔여 간선은 모두 막혀 있다.
>
> 최소 컷의 용량은 **원래 입력 간선 중 S에서 바깥으로 나가는 용량의 합**이다. 위 예에서는 `S={0}`이고 `0→1`의 3과 `0→2`의 2를 합한 5다. source에서 빠져나갈 수 있는 총량 자체가 5이므로 더 큰 유량은 불가능하며, 실제로 5를 보냈으므로 최대 유량과 최소 컷이 일치한다.
>
> 간선의 `remaining`은 이미 바뀐 값이므로 컷의 원래 용량을 합산하려면 입력 용량을 별도로 보관한다. `sourceSideOfMinCut`은 정점 집합만 반환한다.
>
> ### 경계 조건과 변형
>
> - DFS의 초기 한도인 `Long.MAX_VALUE`는 무한 용량 간선을 뜻하지 않는다. 경로에서 보내는 양은 매 간선의 실제 잔여 용량과 `min`을 취해 제한된다.
> - sink에 도달할 경로가 없으면 답은 0이다. 용량이 0인 간선은 잔여 탐색에서 사용할 수 없다.
> - 중간 정점에서는 들어온 유량과 나간 유량이 같아야 한다. 정점 자체에 처리 한도가 있으면 정점을 입구·출구로 나누고 그 사이에 용량 간선을 둔다.
> - 이분 매칭은 `source→왼쪽`, `왼쪽→오른쪽`, `오른쪽→sink` 간선의 용량을 모두 1로 두어 표현할 수 있다.
> - 비용까지 최소화하는 최소 비용 최대 유량과, 간선 아래·위 용량 제한을 함께 다루는 순환 유량은 별도의 모델과 구현이 필요하다.
>
