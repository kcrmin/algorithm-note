# 이분 그래프와 이분 매칭

> 이분 그래프는 모든 간선의 양 끝 색이 다르고, 이분 매칭은 정점이 겹치지 않는 간선들을 증대 경로로 늘린다.

## 개념

이분 그래프는 정점을 두 집합 L과 R로 나누어 모든 간선이 서로 다른 집합을 연결하게 할 수 있는 그래프다. 두 색으로 인접 정점의 색을 다르게 칠할 수 있는지 검사하면 이분 그래프인지 판정할 수 있다.

이분 매칭은 이분 그래프에서 어느 정점도 두 번 사용하지 않도록 고른 간선들의 집합이며, 최대 매칭은 그 간선 수를 가장 크게 만든 결과다. 이미 배정된 간선을 다른 자리로 옮기는 증대 경로를 허용해야 단순히 빈 자리만 고르는 방식보다 더 큰 매칭을 찾을 수 있다.

## 적용 조건

- `color(n, undirectedEdges)`는 정점 `0 ~ n-1`의 무향 그래프를 받는다. 이분 그래프이면 각 정점의 색 `0/1`을 반환하고, 불가능하면 `null`을 반환한다. 시간·공간은 `O(V+E)`다.
- `maximumMatching(L, R, edges)`는 두 집합이 이미 나뉜 입력을 받는다. 각 간선은 `{왼쪽 정점 번호, 오른쪽 정점 번호}`이며 양쪽 번호는 **각각 0부터** 시작한다.
- 최대 매칭은 Kuhn의 DFS 증대 경로 알고리즘이다. 시간 `O(L·E + L + R)`, 공간 `O(L+R+E)`다. 간선 수 E에는 중복 간선도 포함한다.
- `rightOfLeft[left]`와 `leftOfRight[right]`는 짝의 번호이며, 짝이 없으면 `-1`이다. 반환되는 매칭 자체는 여러 답 중 하나다.
- 방문 배열은 탐색 번호로 구분하므로 왼쪽 정점마다 배열 전체를 지우는 추가 비용이 없다. 재귀 깊이는 최악 `O(L)`이며 큰 입력에서는 Java 호출 스택 한계를 고려해야 한다.
- 정점별 수용량이 1인 일대일 배정을 다룬다. 여러 개를 맡길 수 있는 배정은 [[최대 유량]]으로 표현할 수 있다. 간선 가중치 합을 최적화하는 코드는 아니다.

## Java 템플릿

```java
import java.util.*;

class BipartiteMatching {
    // 무방향 그래프: 0/1 색 배열. 이분 그래프가 아니면 null.
    static int[] color(int n, int[][] undirectedEdges) {
        List<List<Integer>> graph = new ArrayList<>();
        for (int i = 0; i < n; i++) graph.add(new ArrayList<>());
        for (int[] edge : undirectedEdges) {
            graph.get(edge[0]).add(edge[1]);
            graph.get(edge[1]).add(edge[0]);
        }
        int[] color = new int[n];
        Arrays.fill(color, -1);
        Queue<Integer> queue = new ArrayDeque<>();
        for (int start = 0; start < n; start++) {
            if (color[start] != -1) continue;
            color[start] = 0;
            queue.offer(start);
            while (!queue.isEmpty()) {
                int current = queue.poll();
                for (int next : graph.get(current)) {
                    if (color[next] == -1) {
                        color[next] = color[current] ^ 1;
                        queue.offer(next);
                    } else if (color[next] == color[current]) {
                        return null;
                    }
                }
            }
        }
        return color;
    }

    static class MatchResult {
        final int size;
        final int[] rightOfLeft;
        final int[] leftOfRight;

        MatchResult(int size, int[] rightOfLeft, int[] leftOfRight) {
            this.size = size;
            this.rightOfLeft = rightOfLeft;
            this.leftOfRight = leftOfRight;
        }
    }

    // edges[i] = {왼쪽 번호, 오른쪽 번호}. 두 집합은 각각 0부터 번호를 매긴다.
    static MatchResult maximumMatching(int leftCount, int rightCount, int[][] edges) {
        List<List<Integer>> graph = new ArrayList<>();
        for (int left = 0; left < leftCount; left++) graph.add(new ArrayList<>());
        for (int[] edge : edges) graph.get(edge[0]).add(edge[1]);

        int[] leftOfRight = new int[rightCount];
        Arrays.fill(leftOfRight, -1);
        int[] seenLeft = new int[leftCount];
        int size = 0;
        for (int left = 0; left < leftCount; left++) {
            int searchId = left + 1; // 탐색마다 방문 표시를 논리적으로 초기화
            if (augment(left, searchId, graph, leftOfRight, seenLeft)) size++;
        }

        int[] rightOfLeft = new int[leftCount];
        Arrays.fill(rightOfLeft, -1);
        for (int right = 0; right < rightCount; right++) {
            int left = leftOfRight[right];
            if (left != -1) rightOfLeft[left] = right;
        }
        return new MatchResult(size, rightOfLeft, leftOfRight);
    }

    private static boolean augment(int left, int searchId,
            List<List<Integer>> graph, int[] leftOfRight, int[] seenLeft) {
        if (seenLeft[left] == searchId) return false;
        seenLeft[left] = searchId;
        for (int right : graph.get(left)) {
            int previous = leftOfRight[right];
            if (previous == -1 || augment(previous, searchId, graph, leftOfRight, seenLeft)) {
                leftOfRight[right] = left;
                return true;
            }
        }
        return false;
    }
}
```

> [!info]- 원리와 코드 설명
>
> ### 1. 이분 판정은 간선을 따라 반대 색을 강제하는 과정이다
>
> 간선이 `0-1, 1-2, 2-3`이면 0을 색 0으로 잡았을 때 색은 `[0,1,0,1]`이 된다. `3-0`을 추가해도 양 끝 색이 다르므로 네 정점의 사이클은 이분 그래프다.
>
> 반면 `0-1, 1-2, 2-0`이면 0의 색은 0, 1의 색은 1, 2의 색은 0이 된다. 마지막 간선 `2-0`의 양 끝이 모두 0이므로 실패한다. 홀수 길이 사이클을 한 바퀴 돌면 시작점에 반대 색을 요구하게 되는 것이다.
>
> `color = -1`은 미방문, `0/1`은 실제 색이다. `color[current] ^ 1`은 `0→1`, `1→0`으로 색을 뒤집는다. 끊긴 그래프에서는 각 연결 요소마다 색칠을 시작해야 하므로 모든 정점에 대한 바깥 반복이 필요하다. 자기 루프는 같은 정점의 색이 자신과 달라야 하므로 즉시 실패한다.
>
> ### 2. 빈 자리만 찾으면 놓치는 배정
>
> 왼쪽은 `L0, L1`, 오른쪽은 `R0, R1`이고 간선은 다음과 같다.
>
> ```text
> L0 — R0
>  │
>  └—— R1
> L1 — R0
> ```
>
> L0가 먼저 R0를 차지하면 L1의 유일한 후보 R0가 이미 차 있다. 하지만 L0는 R1로 옮길 수 있으므로 최종적으로 두 정점을 모두 배정할 수 있다.
>
> | 단계 | `leftOfRight` = [R0의 주인, R1의 주인] | 매칭 수 |
> |---|---|---:|
> | 시작 | `[-1,-1]` | 0 |
> | L0를 R0에 배정 | `[0,-1]` | 1 |
> | L1이 R0의 주인 L0를 재배치 시도 | 아직 `[0,-1]` | 1 |
> | L0를 R1로 재배치 | `[0,0]`인 중간 상태 | 1 |
> | L1을 R0에 배정하여 호출 복귀 | `[1,0]` | 2 |
>
> 재귀 호출 중의 잠깐 중복된 주인은 호출이 성공해서 돌아오는 동안 해소된다. `rightOfLeft`는 모든 탐색이 끝난 뒤 `leftOfRight`에서 복원하므로 이 중간 상태를 별도로 관리할 필요가 없다.
>
> ### 3. 증대 경로가 매칭을 정확히 하나 늘리는 이유
>
> 위 재배치는 `L1 → R0 → L0 → R1`이다. 현재 사용하지 않는 간선과 사용 중인 간선이 번갈아 나오고, 마지막은 빈 오른쪽 정점이다.
>
> 선택을 뒤집으면 기존 매칭 간선 `L0-R0` 하나가 빠지고 `L1-R0`, `L0-R1` 두 개가 들어간다. 따라서 매칭 수가 1 증가한다. 이런 증대 경로가 더 이상 없을 때 매칭의 크기가 최대다.
>
> `previous == -1`이면 바로 빈 자리를 찾은 것이고, 그렇지 않으면 `augment(previous, ...)`가 그 자리에 있던 왼쪽 정점을 다른 자리로 옮길 수 있는지 확인한다. 성공한 재귀 경로에서만 소유자를 바꾸므로 실패한 탐색은 기존 매칭을 유지한다.
>
> ### 4. 방문 표시는 왼쪽 정점마다 새로 시작해야 한다
>
> L0 탐색에서 `seenLeft[0] = 1`이 된다. L1을 시작할 때도 같은 표시를 쓰면 L0를 재탐색할 수 없어 위 재배치를 놓친다.
>
> 코드는 L0 탐색의 `searchId = 1`, L1 탐색의 `searchId = 2`처럼 구분한다. 저장된 값이 **현재 탐색 번호와 같을 때만** 이미 방문한 것으로 판단하므로 이전 탐색 기록은 자동으로 무시된다. 이는 탐색마다 방문 상태를 초기화하는 것과 같다.
>
> 한 번의 탐색 안에서는 같은 왼쪽 정점을 다시 처리하지 않는다. L0가 자신의 현재 자리 R0를 통해 다시 호출되더라도 바로 실패하여 재배치 탐색이 무한히 반복되지 않는다.
>
> ### 경계 조건과 변형
>
> - 이분 **판정**과 최대 **매칭**은 서로 다른 연산이다. `maximumMatching`이 일반 그래프를 자동으로 색칠하거나 두 집합을 나누지는 않는다.
> - 일반 그래프를 색칠한 뒤 매칭 입력으로 바꾸려면 색 0과 색 1의 정점에 각각 새로운 `0 ~ L-1`, `0 ~ R-1` 번호를 부여한다.
> - 더 추가할 간선이 없는 극대 매칭과 간선 수가 가장 큰 최대 매칭은 다르다. 처음 L0-R0 하나만 고른 결과는 극대이지만 최대가 아니다.
> - 최대 매칭 크기가 L이면 모든 왼쪽 정점을 배정한 것이다. 모든 정점을 덮는 완전 매칭은 양쪽 정점 수가 같고 그 크기만큼 배정되어야 한다.
> - L 또는 R이 0이어도 유효하다. 대응하는 간선이 없는 입력에서 크기 0과 모두 `-1`인 짝 배열을 반환한다.
> - 더 큰 이분 그래프에는 여러 증대 경로를 층별로 처리하는 Hopcroft–Karp의 `O(E√(L+R))` 방식이 있다. 위 템플릿의 복잡도는 Kuhn 기준이다.
