# 위상 정렬

> **핵심:** 진입차수 0을 큐에 넣고, 하나를 끝낼 때 다음 작업의 진입차수를 1씩 줄인다.

## 개념

위상 정렬은 유향 그래프에서 모든 선행 정점이 후행 정점보다 앞에 오도록 정점을 나열하는 방법이다. 진입차수가 0인 정점은 남은 선행 조건이 없으므로 지금 처리할 수 있다. 사이클이 있으면 전체 순서를 만들 수 없다.

## 적용 조건

- “A를 끝내야 B를 시작한다” 같은 **선행 관계**를 지키는 순서가 필요할 때 쓴다.
- 간선은 선행 작업→후행 작업 방향이다. 순서가 존재하려면 유향 그래프에 사이클이 없어야 한다.
- 정점은 `0 ~ n-1`, `edges[i]={먼저 할 작업, 나중 할 작업}`이다.
- 시간과 공간은 모두 `O(V+E)`다.
- 가능한 순서가 여러 개일 수 있다. 아래 코드는 그중 하나를 반환하며 가장 작은 번호 순서를 보장하지 않는다.
- 사이클이 있으면 `Optional.empty()`를 반환한다.

## Java 템플릿

```java
import java.util.*;

class TopologicalTemplate {
    static Optional<int[]> order(int n, int[][] edges) {
        List<List<Integer>> graph = new ArrayList<>();
        for (int i = 0; i < n; i++) graph.add(new ArrayList<>());
        int[] indegree = new int[n];

        for (int[] edge : edges) {
            int before = edge[0];
            int after = edge[1];
            graph.get(before).add(after);
            indegree[after]++;
        }

        Queue<Integer> queue = new ArrayDeque<>();
        for (int vertex = 0; vertex < n; vertex++) {
            if (indegree[vertex] == 0) queue.offer(vertex);
        }

        int[] result = new int[n];
        int count = 0;
        while (!queue.isEmpty()) {
            int current = queue.poll();
            result[count++] = current;

            for (int next : graph.get(current)) {
                indegree[next]--;
                if (indegree[next] == 0) queue.offer(next);
            }
        }

        if (count != n) return Optional.empty();
        return Optional.of(result);
    }
}
```

> [!info]- 원리와 코드 설명
>
> 관계가 `0→2`, `1→2`, `2→3`이면 진입차수는 `[0,0,2,1]`이다.
>
> | 꺼낸 작업 | 달라지는 진입차수 | 남은 큐 | 결과 |
> |---:|---|---|---|
> | 시작 | — | `0,1` | 없음 |
> | 0 | `indegree[2]: 2→1` | `1` | `0` |
> | 1 | `indegree[2]: 1→0` | `2` | `0,1` |
> | 2 | `indegree[3]: 1→0` | `3` | `0,1,2` |
> | 3 | 없음 | 비어 있음 | `0,1,2,3` |
>
> 작업 2는 0만 끝났을 때 큐에 들어가면 안 된다. 진입차수 1은 아직 끝나지 않은 선행 작업 1개가 있다는 뜻이다. **모든 선행 작업을 끝내서 0이 되는 순간**에만 준비가 끝난다.
>
> **왜 전체 정점을 꺼냈는지 확인하는가?** `0→1`, `1→0`이면 진입차수는 `[1,1]`이다. 처음부터 큐가 비어 아무것도 꺼내지 못한다. 큐가 비었다고 성공한 것이 아니라, 남은 작업이 서로를 기다리는 사이클이다.
>
> 사이클과 무관한 정점만 먼저 처리되다가 멈추는 경우도 있다. 그래서 시작할 때 큐가 비어 있는지만 보지 않고 마지막에 `count == n`인지 확인한다.
>
> ### 주의점
>
> - 간선 방향을 반대로 저장하면 후행 작업이 먼저 나오는 순서가 된다. “무엇이 먼저인가”를 먼저 적는다.
> - 진입차수는 **들어오는 간선 수**다. 위 코드는 `indegree[after]++`다.
> - BFS와 큐 문법은 같지만, 방문 여부 대신 남은 선행 작업 수가 진입 조건이다.
> - 간선 하나를 처리할 때마다 진입차수를 정확히 한 번 줄인다.
> - 입력 중복 간선을 저장했다면 진입차수도 같은 횟수만큼 세어야 한다. 한쪽만 중복 제거하면 수가 맞지 않는다.
> - 원래 진입차수 배열은 탐색 중 바뀐다. 다시 정렬해야 한다면 원본을 복사하거나 새로 계산한다.
> - `n=0`이면 빈 순서가 정상 결과다. 실패와 빈 배열을 구분하기 위해 `Optional`을 사용한다.
> - 작업 번호가 작은 것을 우선하는 조건이 있다면 준비된 작업을 담는 큐만 [[힙]]으로 바꿀 수 있다.
