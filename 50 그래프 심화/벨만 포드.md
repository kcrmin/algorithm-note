# 벨만 포드

모든 간선을 반복 완화해 음수 간선의 최단거리와 도달 가능한 음수 사이클을 찾는다.

> **기억:** 출발 0·나머지 INF → 전체 간선을 V−1회 완화 → 한 번 더 줄어들면 음수 사이클.

**전제:** V≥1, 유향 간선 목록. 시간 `O(VE)`, 거리 공간 `O(V)`. 모든 중간 합이 long·INF 범위 안이어야 한다.

## 템플릿

`edges`의 Edge는 `from,to,weight`, `distance[source]=0`, 나머지는 INF다. 반환 true는 **출발점에서 도달 가능한** 음수 사이클이 있다는 뜻이다.

```java
static boolean bellmanFord(int vertexCount) {
    for (int round = 1; round < vertexCount; round++) {
        boolean updated = false;
        for (Edge edge : edges) {
            if (distance[edge.from] == INF) continue;
            long candidate = distance[edge.from] + edge.weight;
            if (candidate < distance[edge.to]) {
                distance[edge.to] = candidate;
                updated = true;
            }
        }
        if (!updated) break;
    }
    for (Edge edge : edges) {
        if (distance[edge.from] == INF) continue;
        if (distance[edge.from] + edge.weight < distance[edge.to]) return true;
    }
    return false;
}
```

## 왜 이렇게 쓰나

- 음수 사이클이 없는 최단 경로는 정점을 반복할 필요가 없어 간선이 최대 **V−1개**다. 간선 순서가 나빠도 V−1회면 전파된다.
- 그 뒤에도 줄어들면 정점을 반복하는 더 싼 경로가 있다는 뜻이므로 도달 가능한 음수 사이클이다.
- INF인 출발 간선은 건너뛴다. 그래야 `INF+음수`를 가짜 거리로 만들지 않고 다른 연결 요소의 사이클도 제외한다.

**작게 추적:** 간선 순서 `2→3:2, 1→2:-3, 0→1:4`: 1회 `[0,4,∞,∞]` → 2회 `[0,4,1,∞]` → 3회 `[0,4,1,3]`.

> [!info]- 더 자세한 설명
> ### 기존 전체 구현의 개념과 적용 조건
>
> 벨만 포드는 모든 간선을 반복해서 확인해 최단 거리를 줄이는 알고리즘이다. 최단 경로의 거리가 확정되는 순서에 의존하지 않으므로 음수 간선도 처리할 수 있다. 도달 가능한 음수 사이클이 있으면 사이클을 돌 때마다 거리가 작아져 유한한 최단 거리가 정의되지 않는 정점이 생긴다.
>
> ## 적용 조건
>
> - 음수 가중치가 있는 단일 출발점 최단 거리와 출발점에서 도달 가능한 음수 사이클 판정에 사용한다. 가중치가 모두 0 이상이면 [[다익스트라]]가 보통 더 빠르다.
> - 정점 번호는 `0..V-1`, `V >= 1`이다. 유향 간선 목록을 사용하며, 무향 간선은 양방향 간선 두 개로 넣는다.
> - 시간 `O(VE)`, 거리 배열 공간 `O(V)`, 입력 간선 저장 공간 `O(E)`다.
> - 가중치는 `int`, 거리는 `long`이다. `INF`는 실제로 만들어질 모든 거리보다 커야 하고 `distance + weight`도 안전해야 한다. 보수적인 충분조건은 `V × max(1, E) × 최대 |가중치| < INF`다. 예를 들어 `V ≤ 5,000`, `E ≤ 20,000`, `|w| ≤ 10^9`이면 아래 상수로 안전하다.
>
> 완화란 `distance[from] + weight < distance[to]`일 때 더 짧은 경로를 반영하는 것이다. 출발점이 0이고, 간선 목록이 **아래 순서**로 저장되어 있다고 하자.
>
> `2 → 3 (2)`, `1 → 2 (-3)`, `0 → 1 (4)`, `0 → 3 (10)`
>
> | 전체 간선 검사 횟수 | `d[0]` | `d[1]` | `d[2]` | `d[3]` |
> |---|---|---|---|---|
> | 초기 | 0 | INF | INF | INF |
> | 1회 | 0 | 4 | INF | 10 |
> | 2회 | 0 | 4 | 1 | 10 |
> | 3회 | 0 | 4 | 1 | 3 |
>
> 이 예에서는 뒤쪽 간선이 먼저 검사되어 한 번에 한 단계씩 전파된다. 음수 사이클이 없는 최단 경로는 정점을 반복할 필요가 없어 간선이 최대 `V - 1`개다. 따라서 간선 순서가 불리해도 `V - 1`회면 충분하다. 같은 회차에 바로 갱신하므로 간선 순서에 따라 한 회차에 더 멀리 전파될 수도 있다.
>
> 위 그래프에 `2 → 1 (1)`을 추가하면 `1 → 2 → 1`의 총비용이 `-2`다. 이 두 간선을 순서대로 검사할 때 `(d[1], d[2])`는 `(4, INF) → (2, 1) → (0, -1) → (-2, -3)`처럼 계속 줄어든다. `V - 1`회 뒤에도 완화가 가능하다는 점이 음수 사이클의 증거다.
>
> `distance[from] == INF`인 간선을 건너뛰어야 도달하지 못한 곳에서 가짜 경로가 시작되지 않는다. 이 조건 덕분에 다른 연결 요소의 음수 사이클은 이 출발점의 결과에 영향을 주지 않는다. 한 회차에 아무 값도 바뀌지 않으면 다음 회차도 바뀔 수 없어 조기 종료할 수 있다.
>
> ### 주의점
>
> - `hasReachableNegativeCycle`이 `true`이면 반환 배열을 정상적인 전체 최단 거리 답으로 사용하지 않는다. 어떤 정점이 음수 사이클의 영향을 받는지까지 필요하면 추가 완화가 일어나는 정점에서 그래프 탐색으로 도달 범위를 표시한다.
> - 그래프 **어디에든** 음수 사이클이 있는지 묻는 문제에서는 모든 정점의 초기 거리를 0으로 두거나, 모든 정점으로 0 간선을 갖는 가상 출발점을 추가한다.
> - 도달 불가 판정은 `distance[v] == INF`다. `INF + 음수`를 계산한 뒤 비교하는 방식은 잘못된 도달 판정을 만든다.
> - `V = 1`이면 일반 완화는 0회지만 추가 검사는 해야 음수 자기 루프를 찾을 수 있다. 관련: [[DFS와 그래프]].

> ### 기존 전체 구현
>
>
> ```java
> import java.util.Arrays;
> import java.util.List;
>
> public final class BellmanFord {
>     public static final long INF = Long.MAX_VALUE / 4;
>
>     public static final class Edge {
>         public final int from;
>         public final int to;
>         public final int weight;
>
>         public Edge(int from, int to, int weight) {
>             this.from = from;
>             this.to = to;
>             this.weight = weight;
>         }
>     }
>
>     public static final class Result {
>         public final long[] distance;
>         public final boolean hasReachableNegativeCycle;
>
>         private Result(long[] distance, boolean negativeCycle) {
>             this.distance = distance;
>             this.hasReachableNegativeCycle = negativeCycle;
>         }
>     }
>
>     public static Result shortestPaths(int vertexCount,
>                                        List<Edge> edges, int source) {
>         long[] distance = new long[vertexCount];
>         Arrays.fill(distance, INF);
>         distance[source] = 0;
>
>         for (int round = 1; round < vertexCount; round++) {
>             boolean updated = false;
>             for (Edge edge : edges) {
>                 if (distance[edge.from] == INF) {
>                     continue;
>                 }
>                 long candidate = distance[edge.from] + edge.weight;
>                 if (candidate < distance[edge.to]) {
>                     distance[edge.to] = candidate;
>                     updated = true;
>                 }
>             }
>             if (!updated) {
>                 break;
>             }
>         }
>
>         boolean negativeCycle = false;
>         for (Edge edge : edges) {
>             if (distance[edge.from] == INF) {
>                 continue;
>             }
>             if (distance[edge.from] + edge.weight < distance[edge.to]) {
>                 negativeCycle = true;
>                 break;
>             }
>         }
>         return new Result(distance, negativeCycle);
>     }
> }
> ```
