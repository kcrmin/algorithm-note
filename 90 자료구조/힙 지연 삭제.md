# 힙 지연 삭제

수정·삭제된 힙 기록을 꼭대기에 나타날 때 버린다.

> **기억:** 수정마다 버전은 딱 한 번 증가 → 그 버전으로 새 기록 삽입 → top에서 현재 버전·생존 여부 검사.

**전제:** ID는 0~maxId, 최고 점수·동점은 작은 ID 우선. 버전은 long 범위. 갱신 O(log M), 조회 최악 O(M log M)·각 기록 제거 1회, 공간 O(M+ID 범위). M은 누적 힙 크기.

## 템플릿

`version[id]`, `alive[id]`, `pq<Entry>`를 쓴다. Entry는 id·score·version을 저장하며 비교자/선언은 아래에 있다.

```java
void update(int id, int score) {
    version[id]++;
    alive[id] = true;
    pq.offer(new Entry(id, score, version[id]));
}
void delete(int id) {
    version[id]++;
    alive[id] = false;
}
int topId() {
    while (!pq.isEmpty()) {
        Entry top = pq.peek();
        if (!alive[top.id] || top.version != version[top.id]) {
            pq.poll();
            continue;
        }
        return top.id;
    }
    return -1;
}
```

## 왜 이렇게 쓰나

- 점수를 수정해도 옛 기록은 힙에 남는다. 현재 version과 다르면 낡은 기록이므로 버린다.
- 증가시킨 version을 Entry에 그대로 넣는다. 생성식에서 다시 ++하면 새 기록도 즉시 낡아진다.
- 유효한 top은 peek로 남겨 둔다. 조회 한 번에 많이 버려도 각 기록은 전체 실행에서 한 번만 제거된다.

**추적:** ID1: `(90점,v1)→(50점,v2)`. top의 옛 90점은 `1≠2`라 제거, 새 50점은 유효하다.

> [!info]- 더 자세한 설명
>
> > **핵심:** 갱신할 때 새 버전을 넣고, 꺼낼 때 현재 버전과 다른 과거 원소를 버린다.
>
> ## 개념
>
> 힙 지연 삭제는 수정·삭제된 과거 원소를 즉시 찾아 지우지 않고, 맨 위에 나타났을 때 무효인지 검사해 버리는 방식이다. 원소의 버전과 현재 버전을 비교하면 같은 ID의 여러 기록 중 최신 기록만 유효하게 볼 수 있다.
>
> ## 적용 조건
>
> ID별 점수를 수정·삭제하면서 최고 점수를 반복 조회할 때 쓴다. 일반 PriorityQueue의 중간 원소를 찾아 지우는 일은 선형 탐색이므로, 과거 기록을 남겨 두고 top에서 정리한다. **단순 최솟값 반복 문제에는 [[힙]]만 사용한다.**
>
> ID는 0~maxId, 동점이면 작은 ID 우선. 아래는 최신 버전 수가 long을 넘지 않는 범위를 가정한다. 각 갱신은 `O(log M)`, M은 힙에 누적된 원소 수다. 조회 한 번은 여러 과거 원소를 지울 수 있지만, 각 원소는 전체 실행 동안 한 번만 제거된다.
>
> ID 1의 점수를 90으로 등록하면 현재 버전=1, 힙 원소 `(1,90,1)`이다. 점수를 50으로 바꾸면 현재 버전=2, 새 원소 `(1,50,2)`를 넣는다.
>
> 힙에서는 예전 90점이 먼저 보인다. 하지만 원소 버전 1과 현재 버전 2가 다르므로 버린다. 이후 새 50점 원소는 버전이 일치하므로 유효하다. 삭제할 때는 버전만 올리고 alive=false로 바꿔, 힙 속 과거 기록을 모두 무효화한다.
>
> **갱신에서 버전을 올리는 일은 딱 한 번이다.** 증가 후 Entry 생성 안에서 다시 `version[id]++`를 쓰면 방금 넣은 원소조차 최신 버전과 달라질 수 있다.
>
> ### 주의점
>
> - 힙에 넣은 Entry의 score를 나중에 직접 바꾸지 않는다. 힙 정렬이 자동 복구되지 않는다.
> - topId는 확인 함수이므로 유효 원소를 꺼내지 않는다. 소모하는 문제라면 반환 전에 제거·상태 변경을 설계한다.
> - 갱신이 매우 많으면 과거 원소가 쌓여 메모리를 쓴다. 필요하면 현재 살아 있는 상태로 힙을 재구축한다.
>
> **관련 개념:** [[힙]] · [[해시]] · [[다익스트라]]

> [!example]- 준비 코드 · 전체 구현
>
> ```java
> import java.util.*;
>
> class VersionHeap {
>     static class Entry {
>         int id, score;
>         long version;
>         Entry(int id, int score, long version) {
>             this.id = id;
>             this.score = score;
>             this.version = version;
>         }
>     }
>     long[] version;
>     boolean[] alive;
>     PriorityQueue<Entry> pq = new PriorityQueue<>((a, b) -> {
>         int byScore = Integer.compare(b.score, a.score);
>         return byScore != 0 ? byScore : Integer.compare(a.id, b.id);
>     });
>
>     VersionHeap(int maxId) {
>         version = new long[maxId + 1];
>         alive = new boolean[maxId + 1];
>     }
>     void update(int id, int score) {
>         version[id]++;
>         alive[id] = true;
>         pq.offer(new Entry(id, score, version[id]));
>     }
>     void delete(int id) {
>         version[id]++;
>         alive[id] = false;
>     }
>     int topId() {
>         while (!pq.isEmpty()) {
>             Entry top = pq.peek();
>             if (!alive[top.id] || top.version != version[top.id]) {
>                 pq.poll();
>                 continue;
>             }
>             return top.id;
>         }
>         return -1;
>     }
> }
> ```
