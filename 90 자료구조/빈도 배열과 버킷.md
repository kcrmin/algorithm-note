# 빈도 배열과 버킷

> **핵심:** 값 범위가 작으면 값 자체를 인덱스로 삼아 개수나 그룹을 관리한다.

## 개념

빈도 배열은 각 값이 몇 번 나왔는지 해당 인덱스에 저장한다. 버킷은 원소를 값의 범주별로 나눠 보관하는 방식이며, 범주 수가 작으면 전체 원소 대신 해당 그룹만 처리할 수 있다.

## 적용 조건

아래는 모든 값이 0~maxValue인 정수 배열을 정렬한다. 시간 `O(n+K)`, 공간 `O(n+K)`이며 K=maxValue+1이다. 값 범위가 매우 크면 정렬보다 메모리 비용이 커진다.

## Java 템플릿

```java
class CountingTemplate {
    static int[] sort(int[] arr, int maxValue) {
        int[] count = new int[maxValue + 1];
        for (int value : arr) count[value]++;
        int[] result = new int[arr.length];
        int index = 0;
        for (int value = 0; value <= maxValue; value++) {
            for (int repeat = 0; repeat < count[value]; repeat++) {
                result[index++] = value;
            }
        }
        return result;
    }
}
```

> [!info]- 원리와 코드 설명
>
> `[3,1,3,2]`면 count[1]=1, count[2]=1, count[3]=2다. 값 인덱스를 1→2→3 순으로 읽고 해당 개수만큼 내보내므로 `[1,2,3,3]`이 된다. 원소를 서로 비교하지 않아 n log n 정렬이 필요 없다.
>
> 개수가 아니라 사람들을 점수 1~5별로 보관한다면 `List<Integer>[6]` 같은 점수별 목록이 버킷이다. 모든 사람을 매번 훑는 대신 점수 범주를 먼저 선택할 수 있다. 다만 목록의 특정 ID 삭제가 자동으로 O(1)이 되는 것은 아니다.
>
> ### 주의점
>
> - 음수도 연속된 작은 범위면 value−minValue를 인덱스로 쓴다.
> - 값 범위가 크고 듬성듬성하면 해시나 좌표 압축이 더 적합하다.
> - 이 코드는 값만 정렬하며, 부가 정보가 있는 객체의 안정 정렬을 제공하지 않는다.
