# 백트래킹

> **핵심:** **하나 선택하고 → 다음 자리로 들어가고 → 돌아오면 선택을 되돌린다.**

## 개념

백트래킹은 선택을 하나씩 쌓아 후보를 만들고, 돌아올 때 선택을 되돌려 다른 후보를 만드는 탐색이다. 현재 선택으로 정답을 만들 수 없다는 근거가 있으면 그 아래의 탐색을 생략하는 가지치기를 적용한다.

## 적용 조건

- 순열, 조합, 조건을 만족하는 배치처럼 **후보를 하나씩 만들어 확인**할 때 쓴다.
- 전체 경우를 탐색하되, 정답이 될 수 없는 상태를 만나면 그 아래의 탐색을 중단할 수 있다.
- 기본 템플릿은 서로 다른 값 `n`개 중 `r`개를 뽑아 **순서 있게 나열하는 순열**이다. 같은 인덱스를 두 번 쓰지 않는다.
- 전제는 `0 <= r <= n`이다. `r = 0`이면 아무것도 고르지 않은 빈 순열 하나를 반환한다.
- 결과 개수는 `P(n,r) = n! / (n-r)!`다. 전부 저장하면 결과만으로 `O(r × P(n,r))` 공간이 필요하다.
- 아래 코드의 시간은 상한으로 `O(n × P(n,r))`다(`r >= 1`). 특히 `r = n`이면 `O(n × n!)`다. 결과를 제외한 추가 공간은 `O(n + r)`다.
- 후보 수가 너무 크면 백트래킹만으로 해결되지 않는다. 입력 크기, 가지치기 가능성, 정답만 세어도 되는지 먼저 확인한다.

## Java 템플릿

`solution(new int[] {1, 2, 3}, 2)`는 `[1,2], [1,3], [2,1], [2,3], [3,1], [3,2]`를 만든다.

```java
import java.util.ArrayList;
import java.util.List;

public class Solution {
    static int[] numbers;
    static int targetSize;
    static boolean[] used;
    static List<Integer> path;
    static List<List<Integer>> answer;

    public List<List<Integer>> solution(int[] values, int r) {
        numbers = values;
        targetSize = r;
        used = new boolean[numbers.length];
        path = new ArrayList<>();
        answer = new ArrayList<>();

        dfs(0);
        return answer;
    }

    private static void dfs(int depth) {
        if (depth == targetSize) {
            answer.add(new ArrayList<>(path));
            return;
        }

        for (int i = 0; i < numbers.length; i++) {
            if (used[i]) {
                continue;
            }

            used[i] = true;
            path.add(numbers[i]);
            dfs(depth + 1);
            path.remove(path.size() - 1);
            used[i] = false;
        }
    }
}
```

> [!info]- 원리와 코드 설명
>
> ### 1. `depth`는 지금까지 고른 개수다
>
> 처음에는 `depth = 0`, `path = []`다. 하나를 고르고 호출하면 `depth = 1`이 된다.
> 이 코드에서는 항상 `depth == path.size()`를 유지한다.
> `depth == targetSize`이면 필요한 자리를 모두 채웠으므로 저장하고 즉시 돌아온다.
>
> `return`을 빼면 정답을 저장한 뒤에도 더 고르려고 내려간다. 완성된 후보는 그 자리에서 끝낸다.
>
> ### 2. 복귀한 다음 줄에서 선택을 되돌린다
>
> `numbers = [1,2,3]`, `r = 2`일 때 첫 가지는 다음 순서다.
> `used`의 위치는 값이 아닌 **입력 배열의 인덱스**다. 여기서는 값들이 서로 다르므로 대응이 눈에 보인다.
>
> | 순서 | 동작 | `path` | `used` |
> | --- | --- | --- | --- |
> | 1 | 인덱스 `0`의 값 `1` 선택 | `[1]` | `[true, false, false]` |
> | 2 | 다음 자리에서 `0`은 건너뛰고 값 `2` 선택 | `[1,2]` | `[true, true, false]` |
> | 3 | `depth == 2` → `[1,2]`의 복사본 저장 | `[1,2]` | `[true, true, false]` |
> | 4 | 돌아와서 마지막 값 제거, 인덱스 `1` 사용 해제 | `[1]` | `[true, false, false]` |
> | 5 | 같은 자리의 다음 후보 `3` 선택 | `[1,3]` | `[true, false, true]` |
> | 6 | `[1,3]` 저장 후 `3` 제거·사용 해제 | `[1]` | `[true, false, false]` |
> | 7 | `1`을 고른 호출도 끝남 → `1` 제거·사용 해제 | `[]` | `[false, false, false]` |
>
> 이제 맨 앞자리에서 값 `2`를 골라 `[2,1]`, `[2,3]`을 만들 수 있다.
> `used[i] = false`를 빼면 앞 가지에서 사용했던 값을 다음 가지에서 다시 고를 수 없다.
> `path.remove(...)`를 빼면 이전 후보가 남아 새 후보와 섞인다.
>
> ### 3. 정답에는 `path` 자체가 아니라 복사본을 넣는다
>
> `path`는 탐색 내내 추가와 삭제를 반복하는 **같은 리스트 객체**다.
> `answer.add(path)`를 하면 여러 정답이 모두 그 객체를 가리킨다.
> 탐색 마지막에 `path`가 `[]`로 돌아오면 저장한 정답들도 같은 빈 리스트를 보게 된다.
>
> `new ArrayList<>(path)`는 그 순간의 값들을 새 리스트에 담는다.
> `[1,2]`를 저장한 뒤 원래 `path`에서 `2`를 지워도 저장된 `[1,2]`는 유지된다.
> 원소가 `Integer`인 이 코드에서는 이 복사로 충분하다.
>
> ### 4. 그래프의 `visited`와 순열의 `used`는 의미가 다르다
>
> | 상태 | 의미 | 복귀할 때 |
> | --- | --- | --- |
> | 그래프 DFS의 `visited[v]` | 전체 탐색에서 정점 `v`를 이미 처리했다 | 유지한다 |
> | 순열의 `used[i]` | 현재 만드는 후보에서 인덱스 `i`를 이미 골랐다 | 해제한다 |
>
> `[1,2]`를 만들 때 같은 `1`을 또 쓰면 안 되지만, 다음 후보 `[2,1]`에서는 `1`을 써야 한다.
> 따라서 현재 경로를 벗어날 때만 사용 표시를 되돌린다.
>
> ### 5. 조합은 다음에 고를 인덱스의 시작점을 넘긴다
>
> 조합은 `[1,2]`와 `[2,1]`을 같은 선택으로 본다. **항상 더 큰 인덱스만 고르면** 역순 후보를 만들지 않는다.
> 위 클래스의 `dfs` 대신 다음 메서드를 넣고, `solution()`의 호출을 `dfsCombination(0)`으로 바꾼다.
> 나머지 `numbers`, `targetSize`, `path`, `answer` 초기화는 같다. 조합에서는 `used` 필드와 초기화가 필요 없다.
>
> ```java
> private static void dfsCombination(int start) {
>     if (path.size() == targetSize) {
>         answer.add(new ArrayList<>(path));
>         return;
>     }
>
>     for (int i = start; i < numbers.length; i++) {
>         path.add(numbers[i]);
>         dfsCombination(i + 1);
>         path.remove(path.size() - 1);
>     }
> }
> ```
>
> `[1,2,3]`에서 `2`개를 고르면, 인덱스 `0`을 고른 뒤에는 `1`과 `2`만 고를 수 있다.
> 그래서 `[1,2]`, `[1,3]`이 나온다. 다음에 인덱스 `1`로 시작하면 `2`만 남아 `[2,3]`이 나온다.
> `[2,1]`은 인덱스가 감소해야 하므로 만들어지지 않는다. 조합의 결과 개수는 `C(n,r)`이다.
> 조합에서도 **선택 → 재귀 → 복원**은 그대로이고, 중복 탐색을 막는 방법이 `used`에서 `start`로 바뀐다.
>
> ### 주의점
>
> - **값 중복**: 이 템플릿은 서로 다른 입력 값을 전제로 한다. `[1,1,2]`처럼 같은 값이 여러 인덱스에 있으면 값이 같은 결과가 반복된다. `used`는 값 중복 제거 기능이 아니다.
> - **중복 선택 허용**: 같은 인덱스를 여러 번 골라도 되는 문제는 다른 규칙이다. 현재 순열 코드는 허용하지 않는다.
> - **가지치기**: 앞으로 정답이 될 가능성이 없다는 근거가 있을 때만 중단한다. 예를 들어 모두 양수인 수의 합이 이미 목표를 넘으면 중단할 수 있지만, 음수가 있으면 이 근거는 깨진다.
> - **상태 초기화**: 정적 필드는 객체를 새로 만들어도 공유된다. `solution()`마다 `used`, `path`, `answer`를 새로 만들고 입력·목표 길이도 덮어써야 재호출 결과가 섞이지 않는다.
> - **저장할 필요 없는 문제**: 개수만 필요하면 완성 시 `count++`, 최댓값만 필요하면 완성 시 최댓값 갱신으로 바꾸고 모든 후보를 저장하지 않는다.
> - **자리 수와 값**: 종료 조건은 고른 개수다. `numbers[i] == r`처럼 선택한 값과 목표 길이를 비교하지 않는다.
