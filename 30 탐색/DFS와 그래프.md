# DFS와 그래프

> 암기 한 줄: **현재 정점을 방문 처리하고, 아직 방문하지 않은 이웃으로 깊게 들어간다.**

## 언제 쓰나

- 서로 연결된 정점 찾기, 연결 요소 개수, 그래프 전체 순회처럼 **어디까지 이어지는지** 확인할 때 쓴다.
- 그래프는 정점과 간선으로 나타낸다. 사람과 친구 관계, 컴퓨터와 통신선도 그래프로 바꿀 수 있다.
- 이 템플릿은 정점 번호가 `0`부터 `n - 1`인 **무방향 그래프의 연결 요소 수**를 반환한다.
- 간선은 `edges[i] = {a, b}`로 주어지고, 두 정점 번호는 모두 유효하다고 가정한다.
- 정점 수 `V`, 간선 수 `E`일 때 시간 `O(V + E)`, 공간 `O(V + E)`다. 재귀 호출 스택은 최악 `O(V)`다.
- 같은 비용의 최단 거리를 구하는 문제라면 BFS가 먼저다. DFS의 첫 발견 경로가 최단 경로라는 보장은 없다.

## 외울 템플릿

인접 리스트는 `graph.get(cur)`에 **현재 정점과 직접 연결된 정점 번호들**을 저장한다.
`solution(6, new int[][] {{0, 1}, {1, 2}, {2, 0}, {3, 4}})`의 결과는 `3`이다.

```java
import java.util.ArrayList;
import java.util.List;

public class Solution {
    static List<List<Integer>> graph;
    static boolean[] visited;

    public int solution(int n, int[][] edges) {
        graph = new ArrayList<>();
        for (int i = 0; i < n; i++) {
            graph.add(new ArrayList<>());
        }
        visited = new boolean[n];

        for (int[] edge : edges) {
            int a = edge[0];
            int b = edge[1];
            graph.get(a).add(b);
            graph.get(b).add(a);
        }

        int components = 0;
        for (int start = 0; start < n; start++) {
            if (visited[start]) {
                continue;
            }

            components++;
            dfs(start);
        }
        return components;
    }

    private static void dfs(int cur) {
        visited[cur] = true;

        for (int next : graph.get(cur)) {
            if (!visited[next]) {
                dfs(next);
            }
        }
    }
}
```

## 왜 이렇게 쓰나

### 1. 무방향 간선 한 개는 두 리스트에 넣는다

`0 — 1`이면 `0`에서 `1`로도, `1`에서 `0`으로도 갈 수 있다.
따라서 `graph.get(0).add(1)`과 `graph.get(1).add(0)`이 모두 필요하다.
예시의 인접 리스트는 다음과 같다. 대괄호 안은 이웃을 탐색하는 순서다.

```text
정점 0: [1, 2]
정점 1: [0, 2]
정점 2: [1, 0]
정점 3: [4]
정점 4: [3]
정점 5: []
```

정점 `5`는 간선이 없어도 존재한다. 그래서 간선을 읽기 **전**, 모든 정점의 빈 리스트를 만든다.
간선이 있는 정점만 생성하면 혼자 떨어진 정점을 빠뜨릴 수 있다.

### 2. 들어오자마자 방문 처리해야 순환을 끊는다

정점 `0, 1, 2`에는 `0 → 1 → 2 → 0`으로 돌아올 수 있는 길이 있다.
`dfs(0)`이 시작하자마자 `visited[0] = true`를 실행하면, 나중에 `2`가 `0`을 보아도 다시 들어가지 않는다.

| 호출·복귀 | 판단 | 방문한 정점 |
| --- | --- | --- |
| `dfs(0)` 진입 | `0` 표시, 첫 이웃 `1`로 진입 | `{0}` |
| `dfs(1)` 진입 | `1` 표시, 이웃 `0`은 건너뛰고 `2`로 진입 | `{0, 1}` |
| `dfs(2)` 진입 | `2` 표시, 이웃 `1`, `0`은 모두 방문함 | `{0, 1, 2}` |
| `dfs(2)` 종료 | 호출한 `dfs(1)`의 다음 줄로 복귀 | `{0, 1, 2}` |
| `dfs(1)` 종료 | `dfs(0)`으로 복귀, 다음 이웃 `2`는 건너뜀 | `{0, 1, 2}` |

방문 표시가 없으면 `0 → 1 → 0 → 1 ...`처럼 끝나지 않는다.
여기서 `visited`는 **이번 탐색 전체에서 이미 처리한 정점**이라는 뜻이다. 복귀할 때 `false`로 되돌리지 않는다.

### 3. DFS 한 번은 한 연결 요소를 모두 방문한다

연결 요소는 **서로 길로 이어지는 정점들의 묶음**이다. 예시의 묶음은 `{0,1,2}`, `{3,4}`, `{5}`다.

| 바깥 반복의 `start` | 처리 | `components` |
| --- | --- | --- |
| `0` | 처음 보는 정점 → `dfs(0)`으로 `0,1,2` 방문 | `1` |
| `1`, `2` | 이미 방문했으므로 건너뜀 | `1` |
| `3` | 처음 보는 정점 → `dfs(3)`으로 `3,4` 방문 | `2` |
| `4` | 이미 방문했으므로 건너뜀 | `2` |
| `5` | 처음 보는 정점 → 혼자 있는 `5` 방문 | `3` |

`dfs(0)`만 실행하면 `3, 4, 5`는 방문하지 못한다. 모든 정점에서 시작 여부를 확인해야 전체 그래프를 덮는다.
간선이 전혀 없는 정점도 하나의 연결 요소다. 정점이 `0`개이면 반복이 실행되지 않아 `0`을 반환한다.

### 4. 인접 리스트는 실제로 있는 간선을 따라간다

인접 행렬 `boolean[n][n]`은 연결 여부를 바로 확인할 수 있지만 공간 `O(V²)`가 필요하다.
인접 리스트는 정점마다 이웃만 저장하므로 공간이 `O(V + E)`다.
위 코드에서는 모든 정점이 한 번씩 처리되고, 무방향 간선은 양쪽에서 한 번씩 총 `2E`번 확인된다.
`O(V + 2E)`에서 상수를 빼면 `O(V + E)`다.

## 바꿀 부분과 실수

- **정점 번호**: 입력이 `1..n`이면 간선을 읽을 때 양 끝 번호를 각각 `1`씩 빼서 `0..n-1`로 통일한다. 정점 개수 `n`은 그대로다.
- **방향 그래프**: `a → b`만 허용하면 `graph.get(a).add(b)`만 한다. 이때 위 바깥 반복의 횟수를 무방향 연결 요소 수나 강한 연결 요소 수로 해석하면 안 된다.
- **시작점 하나의 도달 여부**: 특정 정점에서 갈 수 있는 곳만 찾으면 그래프와 `visited`를 만든 뒤 그 정점에서 `dfs()` 한 번만 호출한다.
- **방문 해제**: 그래프 전체 순회에서는 방문을 유지한다. 후보를 만들고 취소하는 백트래킹의 `used`와 목적이 다르다.
- **상태 초기화**: `solution()`을 다시 호출할 때 `graph`와 `visited`를 새로 만든다. 이전 입력의 간선이나 방문 표시가 남으면 결과가 섞인다.
- **재귀 깊이**: 정점이 일렬로 아주 길게 이어지면 Java에서 `StackOverflowError`가 날 수 있다. 이때 `ArrayDeque<Integer>`를 명시적 스택으로 쓰는 반복 DFS로 바꾸고, 스택에 넣을 때 방문 표시한다.
- **거리**: DFS로 기록한 깊이는 탐색 경로의 깊이다. 일반 그래프에서 시작점의 최단 거리로 사용하지 않는다.
