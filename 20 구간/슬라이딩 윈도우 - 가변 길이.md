# 슬라이딩 윈도우 - 가변 길이

양수 배열에서 합이 target 이상인 동안 창을 줄여 **가장 짧은 연속 구간**을 찾는다.

> **기억:** 오른쪽 더하기 → 만족하면 길이 기록 → 왼쪽 빼기 → 만족하는 동안 반복.

**전제:** 모든 원소 `> 0`, `target > 0`. 시간 `O(n)`, 공간 `O(1)`; 음수 배열에는 이 이동 규칙을 쓰지 않는다.

`arr`, `target`을 받는 int 메서드 안에 쓴다. 조건을 만족하는 구간이 없으면 0을 반환한다.

## 템플릿

```java
int left = 0, minLength = Integer.MAX_VALUE;
long sum = 0;
for (int right = 0; right < arr.length; right++) {
    sum += arr[right];
    while (sum >= target) {
        minLength = Math.min(minLength, right - left + 1);
        sum -= arr[left++];
    }
}
return minLength == Integer.MAX_VALUE ? 0 : minLength;
```

## 왜 이렇게 쓰나

- `sum >= target`인 현재 창은 정답 후보다. **먼저 기록**해야 줄이면서 사라질 길이를 놓치지 않는다.
- 하나 빼도 여전히 만족할 수 있으므로 `while`로 더 짧은 창을 계속 확인한다.
- 양수와 target 양수라서 빈 창은 조건을 만족하지 않는다. 포인터는 되돌아가지 않는다.

1. `[2,1,3,2]`, target 5: 처음 2,1의 합은 3이라 계속 확장.
2. 3 추가 → 합 6, 길이 3 기록 → 2 제거, 합 4.
3. 2 추가 → 합 6, 길이 3 기록 → 1 제거, 합 5 → 길이 2 기록.

> [!info]- 더 자세한 설명
> ### 기록 위치가 다른 이유
>
> [[투 포인터 - 연속 구간]]은 합이 정확히 target인지를 찾으므로 초과분을 줄인 **뒤에 확인**한다. 여기서는 target 이상인 모든 구간이 정답 후보이므로 줄이기 **전에 기록**한다.
>
> 위 예시 마지막에는 `[3,2]`의 길이 2까지 기록한 뒤 3을 빼서 sum 2가 된다. 한 번만 줄이는 if였다면 이 길이 2 후보를 놓친다.
>
> ### 음수 주의
>
> 음수를 빼면 합이 오히려 커질 수 있다. 따라서 합이 부족할 때는 확장, 충분할 때는 축소한다는 근거가 깨진다. 이 양수용 최소 길이 템플릿을 음수 배열에 그대로 적용하지 않는다.
>
> 각 원소가 한 번 들어오고 최대 한 번 나가므로 for 안에 while이 있어도 전체 시간은 O(n)이다. 빈 배열이나 정답이 없는 배열은 0이다.
