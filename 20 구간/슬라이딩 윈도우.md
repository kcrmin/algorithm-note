# 슬라이딩 윈도우

길이 k인 연속 구간을 한 칸씩 옮기며 들어온 값과 나간 값만으로 최대 합을 갱신한다.

> **기억:** 오른쪽 더하기 → k 넘으면 왼쪽 빼기 → 정확히 k면 기록.

**전제:** `1 <= k <= arr.length`, 음수·0 허용. 시간 `O(n)`, 공간 `O(1)`.

`arr`, `k`를 받는 long 메서드 안에 쓴다. 현재 구간은 `[left,right]`, 길이는 `right - left + 1`이다.

## 템플릿

```java
int left = 0;
long sum = 0, max = Long.MIN_VALUE;
for (int right = 0; right < arr.length; right++) {
    sum += arr[right];
    if (right - left + 1 > k) {
        sum -= arr[left++];
    }
    if (right - left + 1 == k) {
        max = Math.max(max, sum);
    }
}
return max;
```

## 왜 이렇게 쓰나

- `> k`에서 빼야 길이 k인 후보를 남긴다. `>= k`면 한 칸 일찍 제거한다.
- 한 번에 하나 추가하므로 길이 초과도 하나뿐이다. 제거는 `if` 한 번이면 된다.
- `== k`일 때만 기록하고, 전부 음수여도 되도록 max를 `Long.MIN_VALUE`로 시작한다.

1. `[10,20,30,40]`, k 3: 10, 20을 더해 길이 2라 기록하지 않는다.
2. 30 추가 → 길이 3, 합 60 기록.
3. 40 추가 → 길이 4, 10 제거 → 길이 3, 합 90 기록.

**관련 개념:** [[슬라이딩 윈도우 - 가변 길이]] · [[투 포인터]] · [[누적합]]

> [!info]- 더 자세한 설명
> ### 합의 부호와 무관한 이유
>
> 고정 길이는 합의 크기가 아니라 길이만 보고 제거한다. 따라서 음수와 0도 사용할 수 있다. `[-5,-2,-6]`, k 2의 구간 합은 -7, -8이므로 최대 합은 -7이다. max를 0으로 시작하면 존재하지 않는 합 0을 답으로 남긴다.
>
> ### 여러 질의와 이동 구별
>
> 임의의 구간 합을 반복해서 물으면 [[누적합]]이 편하다. 길이 k의 창을 차례로 옮기며 최댓값만 구할 때는 이전 합에서 나간 값을 빼고 들어온 값을 더하면 충분하다.
>
> 합이 target 이상인 최소 길이를 찾는 창은 길이가 고정되어 있지 않다. [[슬라이딩 윈도우 - 가변 길이]]에서 추가 → 기록 → 축소 순서를 쓴다.
>
> 전체 메서드는 k가 1 미만이거나 배열 길이보다 크면 예외를 던진다. 첫 화면은 유효한 k를 전제로 한다.

>

> static long maxFixedWindow(int[] arr, int k) {
>     if (k < 1 || k > arr.length) {
>         throw new IllegalArgumentException("invalid k");
>     }
>
>     int left = 0;
>     long sum = 0;
>     long max = Long.MIN_VALUE;
>
>     for (int right = 0; right < arr.length; right++) {
>         sum += arr[right];
>
>         if (right - left + 1 > k) {
>             sum -= arr[left++];
>         }
>
>         if (right - left + 1 == k) {
>             max = Math.max(max, sum);
>         }
>     }
>
>     return max;
> }
> ```
