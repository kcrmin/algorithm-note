# 슬라이딩 윈도우

> **핵심:** **고정 길이는 추가 → 초과하면 제거 → 확인, 최소 길이는 추가 → 정답 기록 → 축소.**

## 개념

슬라이딩 윈도우는 연속 구간의 상태를 유지하면서 들어온 값과 나간 값만 갱신하는 방법이다. 길이를 고정하면 원소의 부호와 무관하지만, 합에 따라 길이를 줄이는 방식에는 합이 움직이는 방향을 예측할 수 있는 조건이 필요하다.

## 적용 조건

- 연속 구간을 이동하면서 합이나 원소 개수를 갱신할 때 사용한다.
- **고정 길이 최대 합:** `1 <= k <= arr.length`. 음수와 0이 있어도 된다.
- **합이 target 이상인 최소 길이:** 모든 원소가 양수이고 `target > 0`일 때 아래 템플릿을 쓴다.
- 두 템플릿 모두 시간 `O(n)`, 추가 공간 `O(1)`이다.

현재 구간은 양 끝을 포함한 `[left, right]`다.
구간 길이는 `right - left + 1`이다.
예를 들어 `left = 1`, `right = 3`이면 인덱스 `1, 2, 3`의 **3개**를 고른다.

## Java 템플릿

### 1. 고정 길이 k의 최대 합

```java
static long maxFixedWindow(int[] arr, int k) {
    if (k < 1 || k > arr.length) {
        throw new IllegalArgumentException("invalid k");
    }

    int left = 0;
    long sum = 0;
    long max = Long.MIN_VALUE;

    for (int right = 0; right < arr.length; right++) {
        sum += arr[right];

        if (right - left + 1 > k) {
            sum -= arr[left++];
        }

        if (right - left + 1 == k) {
            max = Math.max(max, sum);
        }
    }

    return max;
}
```

### 2. 합이 target 이상인 최소 길이

전제: 모든 원소가 0보다 크다. 정답 구간이 없으면 `0`을 반환한다.

```java
static int minPositiveWindow(int[] arr, long target) {
    if (target <= 0) {
        throw new IllegalArgumentException("target must be positive");
    }

    int left = 0;
    long sum = 0;
    int minLength = Integer.MAX_VALUE;

    for (int right = 0; right < arr.length; right++) {
        sum += arr[right];

        while (sum >= target) {
            minLength = Math.min(minLength, right - left + 1);
            sum -= arr[left++];
        }
    }

    return minLength == Integer.MAX_VALUE ? 0 : minLength;
}
```

> [!info]- 원리와 코드 설명
>
> ### 고정 길이: `> k`에서 제거하고 `== k`에서 확인한다
>
> `arr = [10, 20, 30, 40]`, `k = 3`이다.
>
> | 추가한 값 | 추가 직후 구간 | 길이 | 처리 |
> | ---: | --- | ---: | --- |
> | `10` | `[10]` | `1` | 아직 확인하지 않음 |
> | `20` | `[10, 20]` | `2` | 아직 확인하지 않음 |
> | `30` | `[10, 20, 30]` | `3` | 합 `60` 기록 |
> | `40` | `[10, 20, 30, 40]` | `4` | `10` 제거 → 합 `90` 기록 |
>
> `> k`인 이유는 길이 `k`인 정답 후보를 유지해야 하기 때문이다.
> `>= k`에서 제거하면 길이가 3이 되는 순간 2로 줄여 버린다.
>
> 제거 후 `== k`인 경우만 기록해야 길이 1, 2짜리 합이 섞이지 않는다.
> 직전 길이가 최대 `k`였고 이번에 하나만 추가했으므로, 초과할 때 **한 번** 빼면 된다.
> 그래서 고정 길이에서는 `if`를 사용한다.
>
> `max = 0`으로 시작하면 `[-5, -2, -6]`, `k = 2`의 정답을 `0`으로 잘못 남긴다.
> 실제 구간 합은 `-7`, `-8`이므로 초기값은 `Long.MIN_VALUE`다.
>
> ### 최소 길이: 정답을 기록한 뒤 줄인다
>
> `arr = [2, 1, 3, 2]`, `target = 5`다.
>
> | right | 추가 후 sum | 조건을 만족하는 동안의 처리 |
> | ---: | ---: | --- |
> | `0` | `2` | 부족하므로 다음 원소 추가 |
> | `1` | `3` | 부족하므로 다음 원소 추가 |
> | `2` | `6` | 길이 `3` 기록 → `2` 제거 → 합 `4`, 중단 |
> | `3` | `6` | 길이 `3` 기록 → `1` 제거 → 합 `5` |
> | `3` 유지 | `5` | 길이 `2` 기록 → `3` 제거 → 합 `2`, 중단 |
>
> `sum >= target`이면 현재 구간이 정답 후보다.
> **지금 길이를 기록하고** 왼쪽 값을 빼야, 축소하면서 사라지는 후보도 놓치지 않는다.
>
> 한 번 줄인 뒤에도 조건을 만족할 수 있으므로 `if` 대신 `while`이다.
> 마지막 행의 `[3, 2]`처럼 길이 2인 구간까지 계속 줄이며 확인한다.
> `sum == target`인 경우도 조건을 만족하므로 `>=`를 사용한다.
>
> 양수만 있으므로 왼쪽을 빼면 합이 작아진다.
> 조건이 깨질 때까지 줄인 뒤에는 오른쪽을 더 늘려야 다시 조건을 만족할 수 있다.
> 이 규칙 덕분에 포인터를 되돌리지 않는다.
>
> ### 주의점
>
> - **정확히 target**과 **target 이상**을 구별한다. 축소 조건과 정답 확인 위치가 달라진다.
> - 고정 길이는 음수여도 괜찮다. 길이만 보고 제거하기 때문이다.
> - 최소 길이 템플릿에 음수가 있으면 합의 변화 방향이 깨지므로 그대로 사용할 수 없다.
> - 양수와 `target > 0` 조건에서는 빈 구간의 합 `0`이 `while`에 들어가지 않는다.
> - 최소 길이 메서드는 빈 배열이나 정답이 없는 배열에서 `0`이다. 고정 길이는 유효한 `k`가 필요하다.
> - 고정 구간의 합을 여러 번 임의로 조회한다면 누적합이 편하다. 한 칸씩 이동하며 최댓값만 구하면 이 템플릿으로 충분하다.
