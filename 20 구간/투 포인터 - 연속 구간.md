# 투 포인터 - 연속 구간

양수 배열에서 오른쪽을 늘리고 넘친 합을 왼쪽에서 줄여 **합이 정확히 target인 연속 구간**을 찾는다.

> **기억:** 오른쪽 더하기 → 초과한 동안 빼기 → 정확한지 확인.

**전제:** 모든 원소 `> 0`, `target > 0`. 시간 `O(n)`, 공간 `O(1)`; 음수가 있으면 [[누적합과 해시]].

`arr`, `target`을 받는 boolean 메서드 안에 쓴다. `[left,right]`는 비어 있지 않은 구간일 때만 확인한다.

## 템플릿

```java
int left = 0;
long sum = 0;
for (int right = 0; right < arr.length; right++) {
    sum += arr[right];
    while (left <= right && sum > target) {
        sum -= arr[left++];
    }
    if (left <= right && sum == target) {
        return true;
    }
}
return false;
```

## 왜 이렇게 쓰나

- 양수라서 오른쪽 추가는 합을 키우고 왼쪽 제거는 합을 줄인다.
- `sum > target`일 때만 줄인다. 같은 합은 확인할 정답이므로 먼저 버리지 않는다.
- `while`로 여러 원소를 뺄 수 있다. 각 원소는 한 번 들어오고 한 번 나가므로 전체 `O(n)`이다.

1. `[2,1,3,2]`, target 5: 2, 1을 더해 sum 3.
2. 3을 더해 6 → 왼쪽 2를 빼면 `[1,3]`, sum 4.
3. 2를 더해 6 → 왼쪽 1을 빼면 `[3,2]`, sum 5 → 발견.

**관련 개념:** [[투 포인터]] · [[슬라이딩 윈도우 - 가변 길이]] · [[누적합과 해시]]

> [!info]- 더 자세한 설명
> ### 빈 구간을 걸러 내는 이유
>
> `[7]`, target 5에서 7을 빼면 `left = 1`, `right = 0`이다. 두 포인터가 역전되었으므로 비어 있는 구간이다. `left <= right`가 실제 원소가 있는지 확인한다.
>
> 전체 메서드는 target이 0 이하이면 false다. 양수 원소를 하나 이상 고른 합은 0 이하가 될 수 없기 때문이다. 첫 화면은 target이 양수라는 전제 아래 커널만 남겼다.
>
> ### 음수면 버릴 근거가 사라진다
>
> `[4,-1]`, target 3에서 4가 크다고 즉시 버리면 나중에 -1을 더해 만들 수 있었던 `[4,-1]`을 놓친다. 음수 배열의 정확한 구간 합은 [[누적합과 해시]]를 쓴다.
>
> 합이 target **이상인 최소 길이**는 기록 위치도 다르다. [[슬라이딩 윈도우 - 가변 길이]]처럼 조건을 만족하는 동안 길이를 먼저 기록하고 줄인다.

> [!example]- 준비 코드 · 전체 구현
> 클래스 안에 두는 전체 메서드다.
>
> ```java
> static boolean hasPositiveWindow(int[] arr, long target) {
>     if (target <= 0) {
>         return false;
>     }
>
>     int left = 0;
>     long sum = 0;
>
>     for (int right = 0; right < arr.length; right++) {
>         sum += arr[right];
>
>         while (left <= right && sum > target) {
>             sum -= arr[left++];
>         }
>
>         if (left <= right && sum == target) {
>             return true;
>         }
>     }
>
>     return false;
> }
> ```
