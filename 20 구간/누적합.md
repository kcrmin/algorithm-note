# 누적합

앞에서부터 쌓은 합 두 개를 빼서 원하는 연속 구간의 합만 남긴다.

> **기억:** 0 한 칸 → 앞에서 쌓기 → 오른쪽 다음 합 − 왼쪽 앞 합.

**전제:** 전처리 후 원소가 바뀌지 않는 배열, `0 <= left <= right < arr.length`, 음수·0 허용. 전처리 `O(n)`, 조회 `O(1)`, 공간 `O(n)`.

`arr`, 양 끝을 포함하는 `left`, `right`를 받는 long 메서드 안이다. 여러 번 조회할 때는 prefix를 한 번만 만든다.

## 템플릿

```java
int n = arr.length;
long[] prefix = new long[n + 1];
for (int i = 0; i < n; i++) {
    prefix[i + 1] = prefix[i] + arr[i];
}

return prefix[right + 1] - prefix[left];
```

## 왜 이렇게 쓰나

- `prefix[i]`는 앞의 **i개** 합이다. `prefix[0] = 0`이라 첫 원소부터인 구간도 같은 식을 쓴다.
- `right + 1`개 합에는 오른쪽 끝 원소까지 들어 있고, `left`개 합을 빼면 왼쪽부터 남는다.
- n개 합과 시작점 0을 함께 담아 `n + 1`칸이다. 합은 long으로 저장한다.

1. `arr = [-2,5,1,-3]` → `prefix = [0,-2,3,4,1]`.
2. `[1,3]`의 합은 `prefix[4] - prefix[1] = 1 - (-2) = 3`.
3. `[0,0]`도 `prefix[1] - prefix[0] = -2`로 별도 분기 없이 계산한다.

**관련 개념:** [[2차원 누적합]] · [[누적합과 해시]] · [[슬라이딩 윈도우]]

> [!info]- 더 자세한 설명
> ### prefix 인덱스는 더한 원소 수
>
> `prefix[i]`에는 `arr[i]`가 아직 들어 있지 않다. `prefix[3]`은 arr[0], arr[1], arr[2]의 합이다. 배열 인덱스와 더한 원소 수를 구별하면 +1 위치를 외우기 쉽다.
>
> `[-2,5,1,-3]`에서 `[2,2]`는 `prefix[3] - prefix[2] = 4 - 3 = 1`, 전체 `[0,3]`은 `prefix[4] - prefix[0] = 1`이다.
>
> 배열마다 buildPrefix를 한 번 호출하고 질의마다 rangeSum만 호출한다. q번 조회하면 전체 O(n + q)다.
>
> ### 경계와 갱신
>
> - 입력 좌표가 1부터 시작하면 left와 right에서 각각 1을 빼서 0 기준으로 바꾼다.
> - 빈 배열의 누적합은 `[0]`이지만, 조회할 수 있는 비어 있지 않은 구간은 없다.
> - 원소가 바뀌면 기존 누적합은 맞지 않는다. 갱신이 잦으면 [[Fenwick 트리]]나 [[세그먼트 트리]]를 본다.
> - 합이 target인 구간의 존재나 개수를 찾을 때는 [[누적합과 해시]]를 결합한다.

> [!example]- 준비 코드 · 전체 구현
> 클래스 안에 두는 전체 메서드다.
>
> ```java
> static long[] buildPrefix(int[] arr) {
>     long[] prefix = new long[arr.length + 1];
>
>     for (int i = 0; i < arr.length; i++) {
>         prefix[i + 1] = prefix[i] + arr[i];
>     }
>
>     return prefix;
> }
> ```
>
> ```java
> static long rangeSum(long[] prefix, int left, int right) {
>     return prefix[right + 1] - prefix[left];
> }
> ```
