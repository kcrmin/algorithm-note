# 누적합

> **핵심:** **앞에서부터 합을 한 번 쌓고, `[left, right]`의 합은 `prefix[right + 1] - prefix[left]`.**

## 개념

누적합은 시작점부터 각 위치까지의 합을 미리 저장한 배열이다. 두 누적합의 차이를 구하면 공통인 앞부분이 사라져 원하는 연속 구간의 합만 남는다.

## 적용 조건

- 배열이 주어지고 **여러 연속 구간의 합**을 반복해서 물을 때 사용한다.
- 구간 길이가 달라도 된다. 고정 길이 구간에만 쓰는 기법이 아니다.
- 음수와 0이 있어도 된다. 덧셈과 뺄셈의 관계만 사용한다.
- 전처리 `O(n)`, 구간 하나의 합 `O(1)`, 추가 공간 `O(n)`.
- 구간을 `q`번 물으면 전체 `O(n + q)`다. 매번 직접 더하면 최악 `O(nq)`다.

`prefix[i]`는 **앞에서 원소를 i개 더한 합**이다.
따라서 `prefix[0] = 0`이고, `prefix[i]`에 `arr[i]`는 들어 있지 않다.

## Java 템플릿

### 1. 누적합 만들기

```java
static long[] buildPrefix(int[] arr) {
    long[] prefix = new long[arr.length + 1];

    for (int i = 0; i < arr.length; i++) {
        prefix[i + 1] = prefix[i] + arr[i];
    }

    return prefix;
}
```

### 2. 양 끝을 포함한 구간 합

전제: `0 <= left <= right < arr.length`이며, `prefix`는 위 메서드로 만든 배열이다.

```java
static long rangeSum(long[] prefix, int left, int right) {
    return prefix[right + 1] - prefix[left];
}
```

배열 하나에 `buildPrefix(arr)`를 **한 번만** 호출한다.
이후 질의마다 `rangeSum(prefix, left, right)`를 호출한다.

> [!info]- 원리와 코드 설명
>
> ### 한 칸 크게 만드는 이유
>
> ```text
> arr 인덱스       0   1   2   3
> arr             -2   5   1  -3
>
> prefix 인덱스    0   1   2   3   4
> prefix           0  -2   3   4   1
> 더한 원소 수      0   1   2   3   4
> ```
>
> 1. 처음 합은 `0`이다. 아직 아무 원소도 더하지 않았다.
> 2. `-2`를 더하면 `prefix[1] = -2`다.
> 3. `5`까지 더하면 `prefix[2] = 3`이다.
> 4. 마지막 `-3`까지 더하면 `prefix[4] = 1`이다.
>
> 원소 4개를 모두 더한 값과 빈 시작점의 합을 함께 저장하므로 칸이 5개 필요하다.
>
> ### `right + 1`과 `left`를 빼는 이유
>
> `[left, right] = [1, 3]`이면 원하는 원소는 `5, 1, -3`이다.
>
> - `prefix[4]`에는 `-2 + 5 + 1 - 3`이 들어 있다.
> - `prefix[1]`에는 구간 앞부분인 `-2`가 들어 있다.
> - 둘을 빼면 `1 - (-2) = 3`으로, 원하는 `5 + 1 - 3`만 남는다.
>
> `right`번 원소까지 포함하려면 **right + 1개**를 더한 값이 필요하다.
> `left`번 원소부터 남기려면 그 앞의 **left개**를 뺀다.
>
> | 구간 | 계산 | 결과 |
> | --- | --- | ---: |
> | `[1, 3]` | `prefix[4] - prefix[1]` | `3` |
> | `[0, 0]` | `prefix[1] - prefix[0]` | `-2` |
> | `[2, 2]` | `prefix[3] - prefix[2]` | `1` |
> | `[0, 3]` | `prefix[4] - prefix[0]` | `1` |
>
> 특히 `left = 0`이어도 `prefix[0] = 0`을 빼면 되므로 별도 조건문이 필요 없다.
>
> ### 주의점
>
> - 입력이 1번부터 시작하면 먼저 `left--`, `right--`로 0번 기준으로 바꾼다.
> - 구간 길이는 `right - left + 1`이다. 누적합 배열의 인덱스와 혼동하지 않는다.
> - 합은 `long`으로 저장한다. `int` 값 여러 개의 합이 `int` 범위를 넘을 수 있다.
> - 빈 배열의 누적합은 `[0]`이지만, 질의할 수 있는 비어 있지 않은 구간은 없다.
> - 원본 원소가 바뀌면 기존 누적합은 맞지 않는다. 수정이 잦은 문제는 다른 자료구조가 필요하다.
> - 합이 `target`인 구간의 존재나 개수를 한 번에 찾으려면 누적합에 해시를 결합한다.
