# 누적합과 해시

현재 누적합에서 target을 뺀 값이 전에 있었는지 찾아 **합이 target인 연속 구간**의 존재를 확인한다.

> **기억:** 시작 합 0 저장 → 현재 합 누적 → sum − target 확인 → 현재 합 저장.

**전제:** 비어 있지 않은 연속 구간, 음수·0·음수 target 허용, 누적합과 차이가 long 범위 안. 평균 시간 `O(n)`, 공간 `O(n)`.

`java.util`의 Set·HashSet을 가져오고 `arr`, `target`을 받는 boolean 메서드 안에 쓴다.

## 템플릿

```java
Set<Long> seen = new HashSet<>();
seen.add(0L);
long sum = 0;
for (int num : arr) {
    sum += num;
    if (seen.contains(sum - target)) {
        return true;
    }
    seen.add(sum);
}
return false;
```

## 왜 이렇게 쓰나

- `현재 합 - 이전 합 = target`이므로 찾을 이전 합은 `sum - target`이다.
- 시작 전 합 0을 넣어야 인덱스 0부터인 구간도 찾는다.
- **확인 후 저장**해야 현재 합 자신과의 차이 0을 빈 구간으로 오인하지 않는다.

1. `[3,-2,4]`, target 2: 시작 seen은 `{0}`, 3 누적 → 필요한 1 없음 → 3 저장.
2. -2 누적 → sum 1, 필요한 -1 없음 → 1 저장.
3. 4 누적 → sum 5, 필요한 3 있음 → `[-2,4]`의 합 2 발견.

**관련 개념:** [[누적합과 해시 - 개수]] · [[누적합]] · [[해시]] · [[투 포인터]]

> [!info]- 더 자세한 설명
> ### 이전 누적합이 시작점을 정한다
>
> 예시의 이전 합 3은 첫 원소까지 읽은 합이다. 현재 합 5에서 3을 빼면 그 다음부터 현재까지인 `[-2,4]`만 남는다. 해시는 모든 시작점을 다시 순회하지 않고 해당 합의 존재를 확인한다.
>
> 같은 배열에서 target 1이면 `[3,-2]`가 답이다. sum 1일 때 필요한 이전 합이 0이므로 시작 전의 0을 저장해 둔다.
>
> ### 순서가 바뀌면 빈 구간을 찾는다
>
> `[5]`, target 0에서 현재 sum 5를 먼저 저장하면 5를 자기 자신에게서 찾는다. 이전 합과 현재 합 사이에 원소가 없는 빈 구간이다. 확인 시점의 해시에는 **현재 위치보다 앞선 누적합만** 있어야 한다.
>
> 음수 배열에서 합이 크다는 이유로 창을 줄이면 뒤의 음수로 만들 수 있던 구간을 놓친다. 누적합과 해시는 값의 증가 방향을 가정하지 않아도 된다.
>
> 존재만 알면 Set이면 충분하다. 구간 개수는 같은 합의 등장 횟수까지 필요하므로 [[누적합과 해시 - 개수]]의 Map을 쓴다. 실제 위치나 최소·최대 길이를 찾으려면 저장할 정보를 인덱스로 바꾼다.

> static boolean hasTargetSum(int[] arr, long target) {
>     java.util.Set<Long> seen = new java.util.HashSet<>();

>     for (int num : arr) {
>         sum += num;
>
>         if (seen.contains(sum - target)) {
>             return true;
>         }
>
>         seen.add(sum);
>     }
>
>     return false;
> }
> ```
