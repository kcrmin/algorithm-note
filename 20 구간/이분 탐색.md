# 이분 탐색

> **핵심:** **FFFTTT의 첫 true는 `right = mid`, TTTFFF의 마지막 true는 `left = mid`와 위쪽 mid.**

## 개념

이분 탐색은 답이 될 수 있는 범위를 절반씩 버리며 경계를 찾는 방법이다. 아래는 후보 값의 가능 여부가 FFFTTT 또는 TTTFFF로 한 번만 바뀌는 **정답 이분 탐색**이며, 참·거짓의 순서가 범위를 버리는 근거다.

## 적용 조건

- 정답 후보를 검사하는 `valid(x)`가 **한 번만 바뀌는 순서**를 가질 때 사용한다.
- `FFFTTT`: 작은 값은 실패하고 큰 값은 성공한다. 성공하는 최소값을 찾는다.
- `TTTFFF`: 작은 값은 성공하고 큰 값은 실패한다. 성공하는 최대값을 찾는다.
- 조건이 `TFTF`처럼 여러 번 바뀌면 아래 템플릿을 쓸 수 없다.
- 후보가 `R - L + 1`개이고 조건 검사 비용이 `C`면 시간 `O(C log(R - L + 1))`, 추가 공간 `O(1)`이다.

여기서는 끝을 모두 포함한 **닫힌 후보 구간 `[left, right]`**을 유지한다.
두 메서드 모두 `0 <= left <= right < Long.MAX_VALUE`를 전제로 한다.
정답이 없으면 `-1`을 반환한다. 따라서 음수 정답을 다루는 템플릿은 아니다.

## Java 템플릿

### 1. FFFTTT: 첫 번째 true

맨 오른쪽도 false면 전부 false다. 이를 먼저 검사해서 해가 없는 경우를 처리한다.

```java
static long firstTrue(long left, long right,
                      java.util.function.LongPredicate valid) {
    if (!valid.test(right)) {
        return -1;
    }

    while (left < right) {
        long mid = left + (right - left) / 2;

        if (valid.test(mid)) {
            right = mid;
        } else {
            left = mid + 1;
        }
    }

    return left;
}
```

### 2. TTTFFF: 마지막 true

맨 왼쪽도 false면 전부 false다. 나머지 구간에 true가 있다고 가정하고 반환하면 안 된다.

```java
static long lastTrue(long left, long right,
                     java.util.function.LongPredicate valid) {
    if (!valid.test(left)) {
        return -1;
    }

    while (left < right) {
        long mid = left + (right - left + 1) / 2;

        if (valid.test(mid)) {
            left = mid;
        } else {
            right = mid - 1;
        }
    }

    return left;
}
```

`valid`는 후보 `long` 하나를 받아 참·거짓을 반환하는 함수다.
예를 들어 `firstTrue(1, 5, x -> x >= 3)`은 `3`을 반환한다.
메서드는 `class Solution` 같은 클래스 안에 넣는다.

> [!info]- 원리와 코드 설명
>
> ### FFFTTT: mid가 정답일 수 있으면 남긴다
>
> 후보 `1, 2, 3, 4, 5`에서 `valid(x) = (x >= 3)`이다.
>
> | 단계 | left | right | mid | 검사와 이동 |
> | ---: | ---: | ---: | ---: | --- |
> | `1` | `1` | `5` | `3` | true → `right = 3` |
> | `2` | `1` | `3` | `2` | false → `left = 3` |
> | 종료 | `3` | `3` | — | 첫 true는 `3` |
>
> **true이면 `right = mid`인 이유:**
> `mid = 3`은 조건을 만족한다. 더 작은 성공값이 있을 수 있으므로 왼쪽을 더 본다.
> 하지만 3 자체가 첫 성공값일 수 있으므로 `mid - 1`로 없애면 안 된다.
>
> **false이면 `left = mid + 1`인 이유:**
> `mid = 2`는 실패다. FFFTTT에서는 그보다 작은 값도 전부 실패다.
> 2까지 모두 버릴 수 있으므로 다음 후보인 3부터 찾는다.
>
> ### TTTFFF: 오른쪽 중간값으로 진행을 보장한다
>
> 후보 `1, 2, 3, 4, 5`에서 `valid(x) = (x <= 3)`이다.
>
> | 단계 | left | right | mid | 검사와 이동 |
> | ---: | ---: | ---: | ---: | --- |
> | `1` | `1` | `5` | `3` | true → `left = 3` |
> | `2` | `3` | `5` | `4` | false → `right = 3` |
> | 종료 | `3` | `3` | — | 마지막 true는 `3` |
>
> **true이면 `left = mid`인 이유:**
> mid는 성공하므로 후보로 남긴다. 더 큰 성공값이 있는지 오른쪽을 찾는다.
>
> **false이면 `right = mid - 1`인 이유:**
> TTTFFF에서는 mid부터 오른쪽이 모두 실패다. mid 자신도 버린다.
>
> **mid 계산에 `+1`이 필요한 이유:**
> `left = 5`, `right = 6`일 때 아래쪽 mid는 5다.
> 5가 true여서 `left = mid`를 실행하면 `left`가 그대로라 반복이 끝나지 않는다.
> 위쪽 mid는 6이므로 true면 `left = 6`, false면 `right = 5`가 되어 반드시 좁아진다.
>
> 두 패턴 모두 `left == right`이면 후보가 하나다.
> 그래서 `while (left < right)`로 끝내고 그 값을 반환한다.
>
> ### 입국심사에 연결하면
>
> `times = [7, 10]`, 필요한 인원이 `6`명이라고 하자.
> 시간 `x`에 처리할 수 있는 사람 수는 `x / 7 + x / 10`이다.
>
> - `x = 20`: `2 + 2 = 4`명 → false.
> - `x = 27`: `3 + 2 = 5`명 → false.
> - `x = 28`: `4 + 2 = 6`명 → true.
> - `x = 30`: `4 + 3 = 7`명 → true.
>
> 시간이 늘면 처리 인원이 줄지 않으므로 FFFTTT다.
> 탐색 구간을 `[0, 7L * 6]`으로 잡으면 가장 빠른 심사관 한 명만 일해도 42분에 모두 처리한다.
> 따라서 오른쪽 끝이 true이며, 첫 true인 28분을 찾는다.
> 위 `firstTrue`와 함께 다음 메서드를 클래스 안에 둔다.
> 전제: `n >= 1`, `times`가 비어 있지 않고 모든 심사 시간이 양수다.
>
> ```java
> static long immigration(int n, int[] times) {
>     int minTime = times[0];
>     for (int duration : times) {
>         minTime = Math.min(minTime, duration);
>     }
>     long right = (long) minTime * n;
>
>     return firstTrue(0, right, time -> {
>         long processed = 0;
>         for (int duration : times) {
>             long capacity = time / duration;
>             if (capacity >= n - processed) {
>                 return true;
>             }
>             processed += capacity;
>         }
>         return false;
>     });
> }
> ```
>
> `(long) minTime * n`은 곱셈 전부터 long으로 계산한다.
> `capacity >= n - processed`면 남은 인원을 이번 심사관이 처리할 수 있으므로 즉시 성공이다.
> 더하기 전에 확인하여 처리 인원 합이 필요 이상으로 커지는 것을 막는다.
>
> ### 주의점
>
> - 문제마다 바꿀 것은 **탐색 범위, valid의 계산, 첫 true/마지막 true 선택**이다.
> - 최솟값·최댓값이라는 표현만 보고 고르지 말고, 후보를 늘렸을 때 참·거짓이 어떻게 바뀌는지 쓴다.
> - 위 두 메서드는 단조성을 검사하지 않는다. 끝점 검사만으로 단조성이 보장되는 것은 아니다.
> - `(left + right) / 2`는 덧셈이 넘칠 수 있다. 위 공식도 극단적인 long 범위를 무조건 지원하지는 않는다.
> - 여기서는 비음수이며 `right < Long.MAX_VALUE`라서 `right - left + 1`까지 안전하다.
>
> 배열의 경계 이름도 구별한다. `arr = [1, 3, 3, 5]`, `target = 3`일 때:
>
> | 이름 | 찾는 위치 | 결과 인덱스 |
> | --- | --- | ---: |
> | lower bound | 처음 `arr[i] >= target` | `1` |
> | upper bound | 처음 `arr[i] > target` | `3` |
> | 마지막 `arr[i] <= target` | TTTFFF의 마지막 true | `2` |
>
> **upper bound는 마지막 true라는 뜻이 아니다.**
> 배열의 lower/upper bound는 해당 위치가 없을 때 보통 `arr.length`를 반환한다.
> 위 메서드의 해 없음 표시 `-1`과 그대로 혼용하지 않는다.
