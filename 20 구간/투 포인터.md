# 투 포인터

정렬된 배열의 양 끝을 좁히며 합이 target인 **서로 다른 두 원소**를 찾는다.

> **기억:** 양 끝 합 → 작으면 왼쪽 증가 → 크면 오른쪽 감소 → 같으면 발견.

**전제:** `arr` 오름차순, 음수 허용, 같은 인덱스 재사용 금지. 시간 `O(n)`, 공간 `O(1)`; 정렬이 필요하면 `O(n log n)` 추가.

`arr`, `target`을 받는 boolean 메서드 안에 쓴다. 원래 인덱스가 필요하면 정렬 전에 함께 보관한다.

## 템플릿

```java
int left = 0, right = arr.length - 1;
while (left < right) {
    long sum = (long) arr[left] + arr[right];
    if (sum == target) {
        return true;
    }
    if (sum < target) {
        left++;
    } else {
        right--;
    }
}
return false;
```

## 왜 이렇게 쓰나

- 합이 작으면 현재 왼쪽 값은 가장 큰 오른쪽 값과도 부족하므로 버린다.
- 합이 크면 현재 오른쪽 값은 가장 작은 왼쪽 값과도 크므로 버린다.
- `left < right`는 한 원소를 두 번 쓰지 않게 하고, `(long)`은 **덧셈 전**에 붙인다.

1. `[-3,-1,2,4,8]`, target 6: `-3 + 8 = 5` → 왼쪽 이동.
2. `-1 + 8 = 7` → 오른쪽 이동, `-1 + 4 = 3` → 왼쪽 이동.
3. `2 + 4 = 6` → 발견.

> [!info]- 더 자세한 설명
> ### 두 원소와 연속 구간 구별
>
> 이 템플릿은 두 원소만 고른다. 두 위치 사이의 중간 원소는 포함하지 않는다. 연속 구간 합을 찾는 같은 방향 포인터는 [[투 포인터 - 연속 구간]]을 본다.
>
> 양 끝 방식의 근거는 정렬에 따른 크기 관계다. 따라서 음수가 있어도 된다. 배열이 정렬되지 않았다면 먼저 정렬해야 하며, 정렬하면 원래 인덱스가 바뀐다.
>
> 각 반복에서 한 포인터가 안쪽으로 움직여 간격이 줄어든다. 빈 배열과 원소 하나인 배열은 반복에 들어가지 않고 false다.
>
> ### 큰 값의 덧셈
>
> `2_000_000_000 + 2_000_000_000`은 int로 더하면 넘친다. `(long) arr[left] + arr[right]`는 처음부터 long 덧셈이다. `(long) (arr[left] + arr[right])`는 넘친 뒤 바꾸므로 늦다.

> [!example]- 준비 코드 · 전체 구현
> 클래스 안에 두는 전체 메서드다.
>
> ```java
> static boolean hasPairSum(int[] arr, long target) {
>     int left = 0;
>     int right = arr.length - 1;
>
>     while (left < right) {
>         long sum = (long) arr[left] + arr[right];
>
>         if (sum == target) {
>             return true;
>         }
>         if (sum < target) {
>             left++;
>         } else {
>             right--;
>         }
>     }
>
>     return false;
> }
> ```
