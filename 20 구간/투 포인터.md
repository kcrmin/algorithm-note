# 투 포인터

> 암기 한 줄: **정렬된 두 수는 양 끝에서, 양수 연속 구간은 확장 → 축소 → 확인.**

## 언제 쓰나

- 두 위치 `left`, `right`를 한 방향으로 움직이며 후보를 버릴 근거가 있을 때 사용한다.
- **양 끝 방식:** 오름차순 배열에서 서로 다른 두 원소의 합이 `target`인지 확인한다. 음수도 가능하다.
- **같은 방향 방식:** 모든 원소가 양수이고 `target > 0`일 때, 합이 정확히 `target`인 연속 구간을 찾는다.
- 두 템플릿 모두 시간 `O(n)`, 추가 공간 `O(1)`이다.
- 양 끝 방식에 정렬이 추가되면 정렬 시간 `O(n log n)`이 별도로 든다.

두 원소를 고르는 문제와 **중간 원소까지 모두 포함하는 연속 구간** 문제를 먼저 구별한다.

## 외울 템플릿

### 1. 양 끝: 정렬 배열의 두 수 합

전제: `arr`가 오름차순이다. 같은 인덱스를 두 번 사용하지 않는다.

```java
static boolean hasPairSum(int[] arr, long target) {
    int left = 0;
    int right = arr.length - 1;

    while (left < right) {
        long sum = (long) arr[left] + arr[right];

        if (sum == target) {
            return true;
        }
        if (sum < target) {
            left++;
        } else {
            right--;
        }
    }

    return false;
}
```

### 2. 같은 방향: 양수 배열의 정확한 구간 합

전제: 모든 원소가 **0보다 크다**. 양수 구간의 합은 양수이므로 `target <= 0`은 바로 실패다.

```java
static boolean hasPositiveWindow(int[] arr, long target) {
    if (target <= 0) {
        return false;
    }

    int left = 0;
    long sum = 0;

    for (int right = 0; right < arr.length; right++) {
        sum += arr[right];

        while (left <= right && sum > target) {
            sum -= arr[left++];
        }

        if (left <= right && sum == target) {
            return true;
        }
    }

    return false;
}
```

## 왜 이렇게 쓰나

### 양 끝: 한쪽 인덱스를 통째로 버릴 수 있다

`arr = [-3, -1, 2, 4, 8]`, `target = 6`이다.

| left 값 | right 값 | 합 | 다음 이동 |
| ---: | ---: | ---: | --- |
| `-3` | `8` | `5` | 작다 → `left++` |
| `-1` | `8` | `7` | 크다 → `right--` |
| `-1` | `4` | `3` | 작다 → `left++` |
| `2` | `4` | `6` | 정답 |

**합이 작을 때 `left++`인 이유:**
현재 왼쪽 값에 후보 중 가장 큰 오른쪽 값을 더해도 부족하다.
오른쪽을 더 작은 값으로 바꾸어도 부족하므로, 현재 왼쪽 값으로는 정답을 만들 수 없다.
왼쪽 값을 버리고 더 큰 값으로 이동한다.

**합이 클 때 `right--`인 이유:**
현재 오른쪽 값에 후보 중 가장 작은 왼쪽 값을 더했는데도 너무 크다.
왼쪽을 더 큰 값으로 바꾸면 합이 더 커지므로, 현재 오른쪽 값도 버릴 수 있다.

음수가 있어도 **정렬에 따른 크기 관계**는 그대로이므로 성립한다.
`left < right`는 서로 다른 두 인덱스만 고르기 위한 조건이다.

### 같은 방향: 양수라서 합의 변화 방향이 일정하다

`arr = [2, 1, 3, 2]`, `target = 5`다.

| right | 추가 후 sum | 너무 크면 제거 | 확인할 구간과 합 |
| ---: | ---: | --- | --- |
| `0` | `2` | 없음 | `[2]`, `2` |
| `1` | `3` | 없음 | `[2, 1]`, `3` |
| `2` | `6` | 왼쪽 `2` 제거 | `[1, 3]`, `4` |
| `3` | `6` | 왼쪽 `1` 제거 | `[3, 2]`, `5` → 정답 |

- 오른쪽 원소를 더하면 합이 커진다. 작은 합은 더 확장해서 확인한다.
- 합이 너무 크면 왼쪽 원소를 빼서 줄인다. 한 번 빼도 클 수 있으므로 `while`이다.
- `sum > target`일 때만 줄인다. `sum == target`인 정답을 먼저 버리면 안 된다.
- `arr[left++]`는 현재 왼쪽 값을 빼고 `left`를 한 칸 옮긴다는 뜻이다.

`[7]`, `target = 5`라면 `7`을 빼서 `left = 1`, `right = 0`이 된다.
이때는 빈 구간이므로 `left <= right`로 비어 있지 않은지 확인한다.

각 원소는 한 번 들어오고 최대 한 번 나간다.
`for` 안에 `while`이 있어도 전체 포인터 이동은 `O(n)`이다.

### 음수가 있으면 같은 이동 규칙이 깨진다

`arr = [4, -1]`, `target = 3`에서 처음 `4`가 크다는 이유로 버리면,
나중에 `-1`을 더해 만들 수 있었던 `[4, -1]`을 놓친다.
음수 배열의 정확한 구간 합은 누적합과 해시를 먼저 떠올린다.

## 바꿀 부분과 실수

- 양 끝 방식은 배열이 정렬되어 있어야 한다. 정렬하면 원래 인덱스는 바뀐다.
- 두 수의 합은 `(long) arr[left] + arr[right]`로 계산한다. 더한 뒤 형변환하면 늦다.
- 양수 구간 템플릿에 음수나 0을 섞어 쓰지 말고, 조건을 바꾸려면 이동 근거부터 다시 확인한다.
- **최소 길이이면서 합이 target 이상**이라면 정답을 기록하는 위치가 달라진다.
- 빈 배열은 두 템플릿 모두 `false`, 원소 하나는 양 끝 방식에서 `false`다.
