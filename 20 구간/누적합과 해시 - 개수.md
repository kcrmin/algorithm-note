# 누적합과 해시 - 개수

이전 누적합의 등장 횟수를 더해 **합이 target인 연속 구간의 개수**를 센다.

> **기억:** 0 한 번 저장 → 현재 합 누적 → 필요한 합 횟수 더하기 → 현재 합 횟수 증가.

**전제:** 비어 있지 않은 연속 구간, 음수·0·음수 target 허용, 합과 차이가 long 범위 안. 평균 시간 `O(n)`, 공간 `O(n)`.

`java.util`의 Map·HashMap을 가져오고 `arr`, `target`을 받는 long 메서드 안에 쓴다.

## 템플릿

```java
Map<Long, Long> count = new HashMap<>();
count.put(0L, 1L);
long sum = 0, answer = 0;
for (int num : arr) {
    sum += num;
    answer += count.getOrDefault(sum - target, 0L);
    count.put(sum, count.getOrDefault(sum, 0L) + 1);
}
return answer;
```

## 왜 이렇게 쓰나

- 같은 이전 합이 2번 나왔다면 서로 다른 시작점 2개이므로 answer에 2를 더한다.
- `0 → 1회`는 배열을 읽기 전 시작점 하나다. 누적 → 확인 → 저장 순서로 빈 구간을 제외한다.
- 개수는 `n(n + 1) / 2`까지 커질 수 있어 answer와 빈도를 long으로 둔다.

1. `[1,-1,1]`, target 1: sum 1, 필요한 0은 1회 → answer 1.
2. sum 0, 필요한 -1은 0회 → answer 1; 저장 후 0은 2회.
3. sum 1, 필요한 0은 2회 → answer 3 (`[1]`, `[1,-1,1]`, 마지막 `[1]`).

> [!info]- 더 자세한 설명
> ### Set으로 세면 안 되는 이유
>
> 마지막 원소를 읽을 때 이전 누적합 0은 배열 시작 전과 두 번째 원소 직후에 각각 있다. 두 시작점을 구별하려면 존재 여부가 아니라 빈도가 필요하다.
>
> `[0,0,0]`, target 0이면 차례로 1, 2, 3개가 추가되어 총 6개다. 현재 합을 먼저 저장하면 매번 빈 구간 하나까지 세므로 9개가 된다.
>
> 빈 배열의 답은 0이고 target 0도 빈 구간은 포함하지 않는다. long 범위 끝에 가까운 target을 허용하면 `sum - target`이 넘치지 않는지 문제 범위를 확인한다.

>

> static long countTargetSum(int[] arr, long target) {
>     java.util.Map<Long, Long> count = new java.util.HashMap<>();
>     count.put(0L, 1L);
>     long sum = 0;
>     long answer = 0;
>
>     for (int num : arr) {
>         sum += num;
>
>         answer += count.getOrDefault(sum - target, 0L);
>         count.put(sum, count.getOrDefault(sum, 0L) + 1);
>     }
>
>     return answer;
> }
> ```
